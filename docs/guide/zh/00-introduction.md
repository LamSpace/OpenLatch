# 00 · 简介与架构

## OpenLatch 是什么

OpenLatch 是一个轻量级分布式锁服务，提供 JUC 风格的协调原语：

- **互斥锁家族**（`OLock`）：可重入锁、简单锁（非可重入）、读写锁（`OReadWriteLock`）、公平锁；
- **分布式信号量**（`OSemaphore`）：N 许可的共享门闸；
- **分布式倒计数屏障**（`OCountDownLatch`）：一次性倒计数栅栏。

后端二选一：**单节点**（内存，零依赖起步）或 **Raft 集群**（Apache Ratis 复制状态机 + 快照，默认 3 节点容忍 1 节点故障）。传输层是 Netty 长连接上的 Protobuf 协议（v3），语义上以**租约**兜底、以**等待-通知-重发**实现 FIFO 公平排队。

一句话定位：**协调，而非共识**。锁会因租约到期或断连被剥夺，业务必须处理失锁回调——这是所有使用方式共同的第一原则（详见 [01 核心概念](01-concepts.md)）。

## 组件全景

```
应用 ── openlatch-client SDK ──或── Spring Boot starter（@OpenLatch 注解）
              │
              ▼  TCP :9410（业务端口，可 TLS/令牌）
      ┌──────────────── 服务端节点 ×N（同一二进制，单机或集群）────────────────┐
      │ Netty 接入层 → 请求分发 → 锁语义核心（状态机/等待队列/租约/会话）      │
      │ 集群形态：Raft 复制（:9411），Leader 处理写、Follower 转发/提示改道    │
      │ 管理面：/metrics + /healthz（:9412，明文）                            │
      └───────────────────────────────────────────────────────────────────────┘
              ▲                                    ▲
   openlatch-console（Web :9413）──── ADMIN_* 只读协议 + /metrics 抓取 ──┘
```

- **客户端可连任意节点**：写请求若落在 Follower，收到 `NOT_LEADER` + Leader 提示自动改道；断线重连经种子列表自报拓扑发现新 Leader。
- **管理面与业务面分离**：`ADMIN_*` 只读观察走业务端口（独立管理令牌逐消息鉴权）；指标/健康走 9412；控制台自身 9413。
- **可观测**：服务端十个指标 + 客户端四个指标，Prometheus 文本格式，详见 [08](08-observability.md)。

## 端口地图（默认值，全部可配置）

| 端口 | 用途 | 明文/TLS |
|---|---|---|
| 9410 | 客户端业务接入（含 `ADMIN_*` 观察流量） | 可选 TLS / mTLS + 业务令牌 |
| 9411 | Raft 节点间复制（仅集群） | 明文（置于内网） |
| 9412 | `/metrics` + `/healthz` 管理端点 | 明文（置于内网） |
| 9413 | 管理控制台 Web UI | 明文（置于内网） |

> 同机部署多个服务端节点时，为每节点配置互异的 `openlatch.server.metrics.port`
> （或 `0` 取临时端口）——该端口绑定冲突会使节点启动失败（fail-fast）。
