# 01 · 核心概念

本篇讲清 OpenLatch 的六个基本机制。读完应当能回答：锁什么时候会丢？丢了客户端如何知道？排队为什么是公平的？

## 1. 租约（Lease）：一切授予都有期限

服务端对每次授予打**租约**：默认 30s（配置区间 1s–1h，客户端自定义值被钳制进区间）。租约到期而未被续持，锁由服务端到期扫描回收、可被重新授予。

**推论：没有"永远持有"的锁。** 网络分区、进程假死、GC 长停顿都可能让"你以为还持有"的锁实际已过租约。写关键状态前问自己：拿锁后做完临界区前锁被别人拿走会怎样？——这个问题的答案就是你要写的失锁处理逻辑。

## 2. 看门狗（Watchdog）：替你按期续租

客户端为每个持有的锁后台续租，周期 = `lease/3`（默认 30s 租约 → 10s 一次）。续租请求失败会重试；持续失败直至租约到期，锁被回收，触发失锁。

- `@OpenLatch` 注解锁与 SDK 锁受同一看门狗保护，包括自定义 `leaseTime` 的锁——租约只是"多久不续就回收"的刻度，不是"到期自动放弃保护"的开关。

## 3. 等待-通知-重发：公平的排队方式

获取不到锁时，客户端不是挂住连接干等，而是**入队后立即拿到 `QUEUED` 应答**；成为队头且锁可用时服务端**推送通知**，客户端**重发**同一个请求拿到授予。好处：

- 服务端不持有"悬挂的响应"，网络抖动不影响队列状态；
- 通知只发给队头，**无惊群**；
- 客户端等待期间连接可复用做别的请求。

队头等待者拿到通知后不回应答（进程已死）时，其席位最多占据一个**队头应答超时**（默认 5s）后被跳过——放弃等待不主动撤销席位，靠这个超时回收。

## 4. FIFO 公平：严格到达序

每个 key 一个等待队列，**按到达顺序授予**，读写锁同样队头优先（读不插队写）。`FAIR` 类型的可重入锁在重入计数与队列交互上保持同序承诺。这是**单个 Leader 任期内的严格 FIFO**：Leader 切换时队列重置为"向新 Leader 重新排队"（位次可能变化——集群形态的公平性边界，见 [05 一致性声明](05-cluster-deployment.md)）。

## 5. 失锁（Lock Lost）：必答题，不是可选题

锁可能因**租约到期**或**会话关闭**（断连、服务端清理）被剥夺。客户端经 `LockLostListener` 通知：

```java
client.addLockLostListener((key, cause) -> {
    // 全局监听：该客户端任意锁丢失都会到达这里
    // 正确姿势：中止/降级正在写的临界区流程 + 告警
});

OLock lock = client.newReentrantLock("order:123");
lock.onLockLost((key, cause) -> { /* 按锁监听，语义同上 */ });
lock.lock();
try {
    doCriticalWork();
} finally {
    lock.unlock();   // 已丢失时 unlock 不报错——以回调为准
}
```

集群形态还有一条隐蔽路径：**failover 回滚**。旧 Leader 已答复"授予成功"但未复制达多数派时崩溃，该授予在新 Leader 上不存在——续租/解锁会以 `INVALID_TOKEN`/`NOT_HELD`/`SESSION_EXPIRED` 失败，同样触发失锁处理。把每次获取视为"可能因 failover 而失效"来设计。

## 6. 超时纪律：不存在无限阻塞

| 层 | 默认 | 语义 |
|---|---|---|
| 单请求超时 `requestTimeout` | 5s | 一次发送等待应答的上限，超时抛 `OpenLatchTimeoutException` |
| `lock()` 总兜底 `defaultWaitTimeout` | 30s | 同步获取的总等待预算，超时抛 `LockAcquisitionTimeoutException` |
| `tryLock(waitTime, unit)` | 自定 | 限时获取，返回布尔 |
| 连接超时 | 3s | TCP + 握手 |

同步 API 永不无限阻塞；异步 API（`lockAsync`/`tryLockAsync`/`acquireAsync`/`releaseAsync`）以异常完成的 future 表达以上失败。

## 7. 原子变量、版本戳与有值引用

`OAtomicLong`/`OAtomicInteger`/`OAtomicBoolean`（协议 v4）与 `OAtomicReference`（协议 v6）
同属 ATOMIC 家族，是库内唯一的**非锁**协调原语：
服务端复制状态里的一个共享可变单元。它与锁的语义差异必须逐条知晓：

- **值不绑定归属**——不属于任何 `(会话, 线程)`。创建者进程死亡、会话超时，值**不回滚、不清零**；
  值的生命周期就是 key 的生命周期。
- **每操作一次网络往返**（写与读皆然）。读不是免费的内存语义；写操作应答自带
  `(value, version)`，"先读后改"应合并成一条带版本 CAS 省一次往返。
- **版本戳**：每次成功改变值的写恰 +1（`GET` 与未命中的 CAS 不推进）。它是
  超时复判与 ABA 消除的唯一依据：`compareAndSetStamped(期望值, 期望版本, 新值)`
  是 ABA-free 形态；JDK 形 `compareAndSet(值, 值)` 仍有值回环风险。
- **超时即效果不确定**：SDK 对超时/改道以**同一序号自动重发**，服务端每 key
  去重槽保证不双加；重发途中会话切换则放弃（抛异常），此时用
  `getStamped()` 复核，MUST NOT 盲目换值重试。
- **条目常驻不回收**：无删除语义，动态生成 key 的场景注意基数治理。
- 溢出语义与 JDK 一致（long/int 按域 wrap，bool 限 {0,1}）。

### 7.1 有值引用与小载荷（v6）

`OAtomicReference` 在标量形态之上引入**一段不透明字节载荷**（对应 JDK `AtomicReference`
的协调面），是二档"小载荷"通道的首个原语：

- **载荷不透明**——服务端只存字节、比较字节，**永不反序列化或解释内容**。对象形态由
  应用层自行编解码（UTF-8 字符串直接用 `String` 便利方法）。这不是实现限制，是定位
  边界：需要按内容检索/分片的正解是 KV 存储，不在本库。
- **尺寸由服务端权威钳制**——每 key 载荷上限 `openlatch.server.limit.max-value-bytes`
  （默认 4KB）。超限写入被**入口拒绝**（`OpenLatchException`，拒绝语义）且零生效——
  超限命令不进入复制日志，集群不会为一段过大的值支付任何复制与快照代价。
  钳制判定只发生在接入层（Leader/单机入口），节点配置漂移不会造成副本分歧；
  **钳制下调不追溯存量**——既有的更大载荷照常可读，后续写入按新限。
- **null 与空字节串是两个可区分的值**——`set(null)` 即清空、`compareAndSet(null, x)`
  可建立空态；空串条目上期望 null 的 CAS 不命中。
- 版本戳、去重槽、同序号重发、超时复判与标量形态**逐项同构**（同一套裁决表）；
  值比较为字节内容相等，`compareAndSetStamped` 同为 ABA-free 形态。
- **无算术面**：没有 `incrementAndGet`/`accumulateAndGet` 对应物（字节串无加法，
  JDK `AtomicReference` 本也没有）。
- **驻留成本可见化**：条目常驻 + 载荷常驻 = 真实的内存与快照尺寸成本。控制台与管理
  协议呈现载荷**大小与截断预览**（全量字节不出现在管理应答中），快照尺寸治理见
  [05 §2/§4.3](05-cluster-deployment.md)。

## 8. 循环屏障与世代

`OBarrier`（协议 v5）对应 JDK `CyclicBarrier`：多方会合、可反复复用。它与 `OCountDownLatch`
的关键差别是**可复用**——每凑满一批到场（一个"世代"）即放行全体并自动开始下一批。
它同样有三处必须知晓的契约差异：

- **离场即破障（增强于 JDK）**——JDK 里参与者线程死亡只是静默不再到场，屏障永远等不满。
  OpenLatch 中任一**已到场**参与方的离开都会即时打破**当前世代**：`await(timeout)` 超时、
  本地中断、显式 `breakBarrier()`、动作执行者抛异常，以及**参与者进程死亡/会话超时**
  （复制状态机的 `SESSION_CLOSE` 应用点裁决）。同世代全体等待者以 `OBrokenBarrierException`
  收场。
- **破障只作用于当前世代（弱于 JDK）**——JDK 的 broken 状态粘滞到 `reset()`；OpenLatch 破障后
  下一批到场自然开启新世代，MUST NOT 被历史破障卡死，因此**不提供 `reset()`**。
  需要"整把屏障作废"时由调用方 `breakBarrier()` 后弃用该 key。
- **`barrierAction` 由最后到场方在其进程内执行**——动作完成回报前其余方不放行（忠实 JDK
  "动作完成前屏障关闭"）；动作抛异常则同世代全体破障。动作执行者进程死亡同样破障，
  其余方不会无限挂起。

世代号每 key 单调递增，应答与放行通知都回显世代，供重发按原世代幂等了结——
**到场是有副作用的请求**：会话切换时在途到场不会自动重放（抛 `OpenLatchException`）。

## 9. 有界队列与延时可见性

`OBlockingQueue`/`ODelayQueue`（协议 v7）对应 JDK `BlockingQueue`/`DelayQueue` 的协调面：
跨进程搬运**小载荷元素**（每元素同受 `max-value-bytes` 钳制，默认 4KB）。它是二档
"载荷通道"的第二个原语——元素随复制日志持久于服务端，与任何会话归属无关：

- **元素绑定 key，不绑定会话（增强于 JDK）**——投递者进程死亡**不吞元素**：JDK 里队列
  随进程堆消散，这里元素是复制状态，存活至被消费。反过来，这也意味着**没有人消费
  就一直驻留**——条目与元素都没有服务端回收路径，忘删 key 是真实的内存/快照成本
  （控制台呈现深度与总驻留字节）。
- **容量必定型（无无界形态）**——首次写入携带的 `capacity` 主张定格容量（服务端上限
  `max-queue-capacity` 默认 1024）；不同句柄对同 key 主张不同容量会被断言拒绝。
  双"满"语义分轨：**元素满**时立即式 `offer` 回 `false`、阻塞式 `put` 挂起等空位；
  **等待挂起队列满**（`max-queue-depth-per-key` 护栏）时挂起请求直接被拒（`OVERLOADED`）。
- **`put/take` 走等待-通知-重发闭环**——与 Latch/Barrier await 同机制：服务端挂起对
  调用方表现为"最终拿到结果或抛错"，Leader 切换后挂起自动重建。应用点竞态回弹
  （预检可满足、提交时被抢先）同样对调用者透明。`offer/poll(timeout)` 的超时是
  客户端本地计时。
- **幂等由每会话去重槽承载**——`put` 应答丢失后的同序号重发**不会双插**；`take`/`drainTo`
  重发交付**同一份字节**（不丢件、不偷吃）。超时后的效果复核用 `size()`/`peek()`。
- **元素不可为 null**——与 `OAtomicReference` 的"null 是一等公民"**看似相仿实则相反**：
  队列沿用 JDK `BlockingQueue` 的 rejectNull 契约，传 null 本地即拒；零长度空字节串
  是合法元素。
- **延时形态（ODelayQueue）**——元素注入时携带相对延迟，**绝对到期时刻由服务端应用点
  以条目时刻折算**并随复制日志确定化（Leader 切换、副本回放不改判）。到期前元素对
  一切消费通道不可见但计入 `size()`；出队按最早到期先出，**同到期保持到达序**
  （增强于 JDK 的无序承诺）。到点唤醒精度为服务端扫描 tick 级
  （`openlatch.server.queue.ready-tick-ms` 默认 200ms）——消费正确性不依赖精度。
  延时注入方法是 `offerDelayed(e, delay, unit)`——**不是** JDK 的
  `offer(e, timeout, unit)`：那个签名在 DelayQueue 里表"延迟"，与阻塞队列族
  表"等待预算"同形异义，故改名防混读。
- **不入面的操作**——无 `iterator`/`contains`/`remove(Object)`（O(n) 字节匹配在 RTT 面
  失真）；批量通道只有 `drainTo`（一次摘多个，摊薄往返；应答受
  `max-drain-bytes` 预算钳制）。

## 10. 广播发布/订阅

`OTopic`（协议 v8）对应 JDK `Flow.Publisher`/`SubmissionPublisher` 的协调面：一个
key 即一个广播通道，发布者每条消息尽力交付给当时在册的全部订阅者。它是二档
"载荷通道"的收口原语，也是项目里**唯一一个不进复制日志的原语**——topic 没有
复制状态，订阅登记是 Leader 内存态，随任期生灭：

- **至多一次（弱化的契约，务必知晓）**——`publish` 返回只表示服务端**已受理并
  入扇出**，不承诺任何订阅者收到；订阅者可能因缓冲满、断线、换主窗口丢消息，
  服务端不重投、不逐条通知。需要"投递必达"的场景请用 `OBlockingQueue`（元素
  持久于复制日志），而不是 topic。
- **弱背压 = drop-newest，两级缓冲（显式契约）**——每订阅服务端在途缓冲
  （`max-subscription-buffer`，默认 256 条）满时**丢弃最新一条**并计数，已入队
  消息照常交付；SDK 本地二级缓冲同策略。一个慢订阅者既不反压发布者，也不被
  断开（与 JDK `SubmissionPublisher` 的 overflow-close 判例刻意不同：断开即会话
  死亡、连带该会话全部持锁释放，代价不对等）。丢弃不逐条通知，只能经
  `droppedCount()` 观察（同任期 `topic_seq` 缺口推断 + 本地溢出计数）。
- **顺序承诺仅限单订阅内、同一 Leader 任期**——同一订阅收到的 `topic_seq`
  严格升序；跨发布者、跨订阅无全局序；Leader 更替后 `topic_seq` 重新起算，
  跨任期的序列号不可比（换主窗口的消息不补投，订阅由客户端自动重挂续收）。
- **发布重试去重仅同 Leader 内**——同序号重发命中服务端每会话去重槽、不双扇出；
  跨换主的重发（含应用层手工重试）**可能双投**，消费侧幂等是应用义务。
- **订阅绑定会话（与队列"死亡不吞元素"刻意相反）**——订阅者进程死亡即退订
  （服务端登记、缓冲、去重槽三路回收）。队列承载驻留数据、topic 承载交付事件：
  数据需要幸存，事件不必。长驻订阅方请显式 `unsubscribe()`，订阅存续有服务端
  登记表与缓冲的常驻成本。
- **载荷与版本纪律沿用二档通则**——消息体不透明字节、必携且不可为 null（零长度
  合法，判例队列元素纪律），逐条受 `max-value-bytes` 入口钳制；topic 消息需
  v8 握手；topic 键与其余家族键同名时受理端只读探测拒绝（尽力而为），
  "一 key 一形态"对 topic 是**应用侧契约**而非机制互斥。

## 11. 条件变量与等待集

`OLock.newCondition(name)`（协议 v9）对应 JDK `Condition`：锁 key 之下的
等待-通知通道。等待集是 **Leader 进程易失态**——不入复制日志、不入快照，
随任期灭失、由客户端自动重挂兜底。它是二档以来第一个不开辟新基建的原语：
await 折叠进既有"等待-通知-重发"获取闭环，signal 家族是纯 Leader 本地的
队列搬运：

- **await = 全量释放折叠 + 唤醒重获取**——await 受理即原子完成"重入计数
  一步清零、租约清除、看门狗停摆 + 挂入等待集"（登记先于释放可见，同关键区
  无丢唤醒窗）；被唤醒后按等待-通知-重发纪律重新获取锁，**返回时持有锁、
  重入从 1 级起**（JDK 同款算术：此前的 N 级已在 await 时清零）。
- **虚假唤醒允许且不承诺杜绝（JDK 同契约，这是语义保真而非降级）**——唤醒
  来源含队首超时清扫促醒、换主重挂窗中已丢失 signal 对应的谓词变化、LEAVE
  与 SIGNAL 的竞态收敛。**守卫循环（guard loop）谓词复查是调用方义务**：
  永远以 `while (!谓词) condition.await();` 包裹，裸 await 即缺陷。
- **命名寻址替代 JDK 句柄身份（适配，不是缺陷）**——条件身份 = (锁 key,
  条件名)：同进程重复 `newCondition("x")`、不同进程对同 key 同名创建的句柄，
  均绑定服务端**同一个等待集**；不同 name 的集合互相隔离。JDK 的句柄身份
  无法跨进程，这里以命名寻址换成跨进程等价的能力面。
- **signal 须持有归属（双层分轨权限）**——`signal`/`signalAll` 要求调用者
  (会话, 线程) 恰为当前持有者：SDK 本地先行检查（误用即抛
  `IllegalMonitorStateException`、零请求），服务端权威复查（线路拒绝码
  `NOT_HELD` 同映射）。`await` 的权限检查**只在本地**——服务端不查登记者
  是否持有（跨换主重挂必经：重挂时旧会话持有已随会话关闭释放）；误用/恶意
  登记为 ghost 等待项，受合并深度护栏（与等待队列合计 `max-queue-depth-per-key`）
  与三路清理（LEAVE/会话死亡/换主）钳制——ghost 与"谓词竞态"不可区分本就是
  JDK 并发常识面。
- **"等待是承诺、signal 是事件"（换主分层语义）**——await 经复制日志：释放
  半程随重放确定生效（承诺幸存），等待集换主清零后由 SDK **自动重挂**等待项；
  但 SIGNAL/SIGNAL_ALL 不入日志、不补偿——**换主窗口内发出的 signal 丢失**，
  等待者至多重挂后等下一次 signal 或本地超时（timed await 是应用自救面）。
  与 topic 的"至多一次、换主窗不重放"同一判例口径：服务端不为应用保管事件
  类状态。
- **等待者无租约、持有者死亡不代为唤醒**——持有者进程死亡或租约到期时，
  服务端 sweep 释放锁并唤醒**等待队列入队者**，但不动条件等待者——无人
  signal 则条件等待者永睡（JDK 对齐；**推荐 `await(timeout, unit)` 形态**）。
  等待者自身无租约、无续租义务。
- **支持面收窄**——仅 REENTRANT/FAIR/SIMPLE 三互斥形态可挂条件；读写锁句柄
  `newCondition` 抛 `UnsupportedOperationException`（本地裁决）。公平锁位次
  延伸：搬运项按**搬运时刻**入 FIFO，被 signal 者不优先于已入队的先辈
  （JDK 非公平同款效果；公平承诺只约束入队序）。

## 12. Phaser 与相位会合

`OClient.newPhaser(key[, initialParties])`（协议 v10）对应 JDK `Phaser`：
跨进程多方**按相位**会合的泛化结构——参与者随进随出、到场与等待解耦、
相位号单调递增不复用。与循环屏障（v5）的关系是"泛化"而非替换：barrier 的
固定 parties、一次到场即全组放行、离场即破障三条在 phaser 分别变为**动态
注册配额**、**到场可不等**（`arrive` 与 `arriveAndAwaitAdvance` 分离）、
**死亡摘除不炸锅**。账簿（配额/到场计数/相位）是复制状态——逐条经日志、
跨换主与重启存续；等待簿记是 Leader 本地态（判例 v9 双拓扑）。它是三档中
机制复用度最高的原语：等待推送复用 `AWAIT_NOTIFY`，去重、护栏、重挂纪律全部
沿用既有判例族。

- **配额按会话记账（与 JDK 匿名 party 的关键差异）**——`register`/
  `bulkRegister(n)` 把配额计入**调用会话**；`arriveAndDeregister` 只能扣
  本会话配额，透支被显式拒绝（JDK 此处本属未定义行为，我们显式从严——
  这样参与者进程死亡时"该摘多少"有确定归属域）。重复 `register()` 即
  重复注册（与 JDK 同判）。
- **到场是状态迁移（全入日志）**——注册、到场、离场逐条经 Raft 提交：
  应到集合与到场计数决定未来合拢，必须是复制态（判例 v5 Barrier，与
  Latch"计数进、等待不入"同族）。合拢判据 `到场数 > 0 且 ≥ 注册总数`，
  推进后计数清零、注册**跨相位存续**（离场才减员——JDK 同判）。
- **重发幂等分两层**——到场的去重键是 (会话, 请求)，只在**当相位**有效
  （槽随推进清空）；推进前一次的到场随"换代窗口"保留一个周期——应答
  丢失的同请求重发跨推进到达时终态回显到场相位、不双计数；更早窗口的迟到
  重发按新到场计（显式声明的竞态，窗口下界同屏障了结记录口径）。注册的
  幂等槽是每会话最近一次 (请求, 相位)——应答丢失重发不双加配额。
- **死亡语义：隐式摘除、已到场事实不撤销、不空转**——参与者会话死亡时其
  注册配额从应到集合即时减除（应到集合缩小可**当场合拢**唤醒存活方——
  单死者不饿死全场），但**已计入的到场不回退**（发生过的计次是复制态事实，
  与队列"死亡不吞元素"对偶）。与屏障对照：barrier 死亡→破障（固定 parties
  下缺席者会饿死全场，破障是唯一温和解）；phaser 动态成员性让"摘除"取代
  "破障"——这是泛化的兑现点，也是两者契约差异最大的一处。
- **归零=空转，不终止（与 JDK 相反，显式声明）**——JDK 的注册数归零经
  `onAdvance`/`arriveAndDeregister` 可把 Phaser 钉死在终止态；本库刻意
  不提供终止（`isTerminated` 无对应词）：全员离场后 key 空转，后续
  `register` 自当前相位恢复运转。理由与屏障拒绝粘滞破障同轴——一批死者的
  影响不该卡住未来所有无辜参与者。
- **三个不提供（Non-Goal）**——无 `onAdvance` 钩子（服务端不执行用户代码；
  以 `arriveAndAwaitAdvance()` 返回的到场相位号判别"该相位由我触达"后本地
  执行动作是替代惯用法，但与他人醒转无先后保证）；无终止态（上一条）；
  无父子分层派生（分层是本地计数器优化，分布式下每到场一次 RTT，红利在
  RTT 瓶颈前消失）。另：相位号为 `long`（JDK `int` 在 2^31 相位后回绕，
  账簿为 long 单调）。
- **等待可跨换主无损自愈（强于 v9 条件的对照面）**——`awaitAdvance(phase)`
  的唤醒谓词"当前相位 > 已见相位"由复制账簿承载：换主窗内丢失的唤醒推送
  由重发/重挂即刻补了结，**无需补偿也无丢失窗**。`awaitAdvance(0)` 合法
  （`phase` 为已见值）；旁观等待**不要求**注册配额（JDK 同款）。
  `awaitAdvance(int)` 有等待总超时兜底（默认 30s 后抛
  `OpenLatchTimeoutException`，循环重入等效 JDK 无限等待——超时纪律延伸，
  不存在事实永挂路径）；`awaitAdvanceInterruptibly(phase, timeout, unit)`
  到期先尽力 CANCEL 撤销再抛 `TimeoutException`（撤销丢失由护栏与清理兜底）。
- **读数是网络往返、Leader 本地零日志**——`getPhase()`/`getRegisteredParties()`
  等每次一条 QUERY（JDK 的纳秒级本地读在此是 RTT 级；高频观察请应用侧缓存
  节流）。读数为 advisory 语义、**不承诺线性化伴随**——与 v4 原子 GET
  "读亦经提交"的判例刻意不一致（相位读数返回即刻可能过期是 JDK 语言事实）。
- **配额与深度两护栏分轨**——`max-parties-per-phaser`（默认 1024）限单键
  注册总数（超限 `OVERLOADED`、既有参与者零扰动，判定唯一在受理点）；挂起
  等待受 `max-queue-depth-per-key` 合并口径（超限 `OVERLOADED`，等待零
  扰动），`arriveAndAwaitAdvance` 的挂起半程恒宽容（到场事实不绞杀）。指标
  侧两超限同码 `OVERLOADED` 以 `op` 标签分轨（register 线 vs await 线）。

## 13. Timer 与定时单次标记

`OClient.newTimer(key)`（协议 v11）对应 JDK `java.util.Timer` 的**可判定子集**：
装载一枚会在未来某刻响一次、**全体共见**的标记。与有界队列的延时形态（v7）
是"延时语义"的两台机器——队列承载**延时交接**（一元素恰一消费者、到期即入
可见集、不可改期撤销），timer 承载**广播单次标记**（一次装载全体共见、可改期
可撤销、不消耗）。"到期后大家都能看到钟响了"用 timer，"延时把活交给一个人"
用 `ODelayQueue`。

- **到期是派生谓词，不是状态迁移（本原语的核心裁决）**——账簿只存
  `{代次, 装载态 armed, 绝对到期时刻}`；`已否到期 = armed ∧ 判定时刻 ≥ 到期时刻`
  是账簿与钟的纯函数。**装载（schedule）与撤销（disarm）经 Raft 日志**（它们
  决定"未来某刻对谁可见"是复制态迁移），但**时钟走过到期点日志恒零新增**——
  没有"fire 事件"条目、没有"已响"位可置（与租约"到期是状态迁移故必须入日志"
  构成判例两端）。到点唤醒是 Leader 侧 tick 扫描的**纯提示**，漏扫不丢状态、
  等待方重发谓词重评即自洽（唤醒精度 tick 级，正确性不依赖精度）。
- **单次与粘滞共见**——一次装载恰一发；到点后一切到达的 `await`/`isFired`
  恒即刻通过（标记不需要被"取走"，这与队列 take 消费形成本质差别）。"再来一次"
  = 重新 `schedule`（换代清钟、代次 +1、旧粘滞标记归伪）。
- **改期以最新代为准**——重装载换代清钟，已挂起的 `await` 以最新代到期时刻为准
  （推后多睡、提前先响皆合法，无"旧代承诺"补偿——推荐 timed await 自救）。
  `disarm` 使当代终结（永不再可标记，直到下一次 `schedule`），并**即时唤醒**
  全体在等旁观者以异常收束（撤销靠事件、不等到期 tick）。
- **装载者死亡钟照响（死亡语义第三形态）**——触发绑定 key 不绑定会话，装载者
  进程死亡**账簿零扰动**、标记照响、旁观者照共见。与屏障"死亡即破障"、phaser
  "死亡即隐式摘除配额"并列——这是 timer 相对进程本地 `java.util.Timer` 的核心
  增量：触发是一个与发起方生命无关的未来事件。等待位随会话灭（订阅随会话消亡）。
- **等待可跨换主无损自愈**——`await` 的谓词在复制账簿，换主窗内丢失的唤醒由
  重发即刻补了结（已到期 `OK`、已撤销异常收束、未到期续挂），无补偿无丢失窗
  （沿 phaser 同侧证据，对照条件 signal 丢失窗的可靠性分层差异）。
- **三个不提供（Non-Goal）**——无任务载荷/回调（服务端不执行用户代码，触发形态
  是标记位与等待唤醒而非 `TimerTask`）；无周期重挂（`schedule(task, delay, period)`
  不提供——服务端周期自触即常驻重发变异，与"到期零条目"裁决相反，客户端循环
  `schedule` 即等价）；无绝对时刻装载（`scheduleAt(Instant)` 不收——客户端墙钟
  偏差注入账簿即污染谓词判据，仅收相对延迟、绝对到期时刻恒由服务端应用点折算）。
- **读数与呈现的时钟口径**——`isFired`/`isArmed`/`getRemainingMillis` 是 Leader
  本地 advisory 读数（即刻过期是契约）；"已否到期"判定随判定节点本地时钟，
  跨节点可见偏差 ≤ 节点间时钟偏移（显式降级声明）。管理呈现面**不折算**——
  恒呈原始 `{代次, armed, fire_at_ms}`，各节点等值、无时钟歧义（"两台机器对
  同一钟的已否到期可能在毫秒窗内不一致"，判据取呈现面原始读数）。
- **护栏与深度**——`max-timer-horizon-ms`（默认 24h）限单次装载相对延迟（超限
  `INVALID_REQUEST` 参数线，防"永远不响的钟"占驻账簿，判定唯一在受理点）；
  `timer-ready-tick-ms`（默认 200ms）定到期唤醒精度（与队列 tick 分名分值分轨）；
  挂起等待受 `max-queue-depth-per-key` 合并口径（超限 `OVERLOADED`）。指标
  `timer.total{op,status}` 与 `timer.fired.total`（唤醒面事件计数，静默到期零计数）。

## 各原语的语义速查

| 原语 | 重入 | 关键语义 |
|---|---|---|
| 可重入锁 | ✅ | 同线程计数；跨线程互斥 |
| 简单锁 | ❌ | 同线程再次获取会**排在自己的队后直至租约到期**——语义如此，不是 bug |
| 读写锁 | 写重入✅ | 无升/降级特判：持读要写、持写要读都走通用排队（会自锁到租约） |
| 公平锁 | ✅ | 显式公平承诺，与可重入锁逐项等价 + 严格 FIFO |
| 信号量 | — | N 许可门闸；`release` 超持有量抛 `IllegalMonitorStateException` |
| 倒计数屏障 | — | 一次性：`init` 定型 total，`countDown` 倒计数至零放行所有 `await`；条目存续至节点重启 |
| 原子变量 | — | 值不绑定归属（死亡不回滚）；每写版本戳 +1；ABA 仅 `*Stamped` 形态消除；条目常驻不回收（v4） |
| 有值引用 | — | 不透明载荷 ≤`maxValueBytes`（默认 4KB，入口权威钳制、超限零生效）；null 与空串两态可区分；版本戳/去重与标量同构；条目与载荷常驻（v6） |
| 循环屏障 | — | 多方会合、可复用世代；**离场即破障**（死亡/超时/中断/显式 break 打破当前世代，增强于 JDK）；破障不粘滞、无 `reset()`；动作由最后到场方执行（v5） |
| 有界队列 | — | 元素绑定 key 不绑定会话（**死亡不吞元素**，增强于 JDK）；容量必定型、双"满"分轨（元素满=`false`/挂起，等待满=`OVERLOADED`）；去重槽保证不双插/同份重放；元素不可为 null；延时形态到期应用点折算、同到期 FIFO（v7） |
| 广播 topic | — | 至多一次；弱背压 drop-newest 两级缓冲（不反压、不断连）；单订阅内同任期 seq 升序、换主重新起算；去重仅同 Leader（跨换主重试可双投，消费侧幂等义务）；**死亡即退订**（与队列相反）；"一 key 一形态"为应用契约（v8） |
| 条件变量 | 随宿主锁 | await 全量释放折叠、唤醒重获取**返回时持锁**（重入从 1 级起）；虚假唤醒允许，**guard loop 是调用方义务**；signal 须持有（服务端权威 + 本地先行双层），await 权限仅本地检查（显式降级）；命名寻址 (key,name) 跨进程等价；**等待是承诺、signal 是事件**（换主自动重挂、窗内 signal 不补偿）；等待者无租约、持有者死亡不代为 signal（推荐 timed await）；读写形态不支持；等待人数并入 key 等待合计护栏（v9） |
| 相位器 | — | 动态注册配额按会话记账（`arriveAndDeregister` 透支拒绝）；到场/注册/离场逐条经日志，**注册跨相位存续、离场才减员**；合拢=到场≥注册且当场唤醒；**死亡隐式摘除且不空转、已到场事实不撤销**（对照屏障"死亡即破障"）；归零空转不终止；无钩子/无分层/相位 long（三 Non-Goal）；等待谓词在账簿——**跨换主自愈**（对照条件 signal 丢失窗）；读数每调一 RTT、advisory 非配对线性化；`awaitAdvance` 有总超时兜底（v10） |
| 延时触发 | — | 定时单次标记：**到期=账簿与钟的派生谓词**（装载/撤销入日志、**时钟过点零条目**、与租约"到期入日志"两端）；一次装载全体共见、不消耗（对照队列"一元素一消费者"）；**重装载换代清钟、改期以最新代为准**；`disarm` 代终结即时唤醒在等者以异常收束；**装载者死亡钟照响**（死亡第三形态，与屏障破障/phaser 摘除并列）；等待谓词在账簿——**跨换主自愈**；无周期/无回调/无绝对时刻（三 Non-Goal）；读数随节点钟、跨节点偏差≤钟偏移（呈现面不折算）；`await` 撤销异常与超时 false 两形态不混读；horizon/tick 两限额（v11） |
