# Design

## Context

动机与回退证据见 `proposal.md`。以下只记录塑造方案的现状与约束。

- **路由是全局拉取点**：`OpenLatchClient.latchRoute()` 有近 50 个调用点，遍布八个非 ACQUIRE 族。各族取用姿势不一——相位器/定时器/屏障在环内多点重取，队列在三个分支重取（`NOT_LEADER` 分支**不**重取），**原子族在 `execute` 的每一轮迭代都重取**。因此"全局换道"对原子族不是可能撞上，而是下一轮必然撞上。
- **回退轮的真实失效链**：周期核对直接改全局路由 → 原子写循环下一轮发现会话已换 → 严格换代守卫抛 `SESSION_EXPIRED`；缺码形护栏落地**之前**，同窗还可能把缺码形应答读成 `value=0`（静默错值）。旧设计声称"不接线在途等待与重发环"，但该承诺在其结构下**不可成立**——它没有能力阻止全局拉取。
- **非 ACQUIRE 拒绝不带地址**：`QueueOpResponse`/`AtomicOpResponse` 等载荷**没有** Leader 提示字段（只有 `AcquireResponse`/`HelloResponse` 有）。所以队列/原子类请求被拒时只被告知"你错了"，不被告知"对的是谁"——**收敛必须自带一次发现动作**。
- **族的采用能力不对称**：只有队列实现了"明确零生效后允许跨会话续发"的逃逸（`noEffectReject`）；原子/相位器/闩/屏障/订阅为严格守卫（换会话即抛）；条件/定时器无守卫。该语义正在由先行 change `fix-queue-noeffect-monotonic` 收紧为**单调不确定闩**。
- **红先判据已就位**：两枚确定性夹具（启动窗提示滞后 / home 驻留非权威节点）由 `@Tag("w11-repro")` + `-Pw11-repro` 门控，无修复时恒红；它们是本 change 的验收判据，不是回归网。
- **既有条款与实现面的偏差（须核实）**：规格条款 4 写"连续 3 次**业务请求**收到 `NOT_LEADER` MUST 触发一次种子发现"，而实现上连续计数与强制发现只挂在**获取（等待）路径**；非获取类请求既不计入也不触发。

## Goals / Non-Goals

**Goals:**

- 让两个根因窗内（home 驻留非权威节点 / 启动窗提示滞后）的非 ACQUIRE 请求在既有等待预算内**收敛**，由两枚红先夹具翻绿来判定。
- 让"刷新路由"这一动作**结构上不可能**把在途请求推入失败——即把回退轮的失效链从根上拆掉，而非靠约定。
- 让库在**稳态零流量**：不为罕见窗口支付恒定探测成本。

**Non-Goals:**

- 不改 wire 协议（不扩拒绝字段）、不改服务端、不新增配置项。
- 不改 ACQUIRE 车道既有语义与阈值路径。
- 不做车道级改道编排统一化（不合并获取与非获取为单一状态机）。
- 不追求"零显式失败"：窗内尚未选出 Leader 时的显式失败仍是合法终态。

## Decisions

### D1 判定权归请求：全局路由可刷新，在途请求不因之重取

**采纳**：请求起手钉住自己的路由；仅在**自身**观察到路由不可用（明确零生效拒绝、连接断开、会话换代）时重取全局路由。全局路由的变更本身**不构成**重取理由。

这条正是旧设计缺的那块砖：它使"刷新"不再需要背负安全性——无论刷新怎么改全局路由，都抽不走别人脚下的路。

| 备选 | 否决理由 |
|---|---|
| 维持全局拉取（回退轮之前的状态） | 任何全局改道都会钻进在途循环；原子族必抛 `SESSION_EXPIRED`。 |
| 全族严格钉死（永不重取全局路由） | 会拖死换主后的写：车道连接已死时若不重取，请求只能耗尽预算——打掉既有严格锚。 |

### D2 触发器：惰性共享刷新（T2′）

**采纳**：`RouteRefresh` —— 单飞（同刻至多一次在飞）+ 限频（最小间隔）+ 在飞期间触发合并；首个被拒请求触发，结果发布为期望路由并建/换车道。稳态零流量。

| 备选 | 否决理由 |
|---|---|
| T1 无条件周期探测 | 库形态下恒定每秒一个包的稳态成本；**不是不可行**（D1 已使其安全），但为罕见窗口长期付费。 |
| T2 逐请求同步探测 | **自我否决**：坏窗内的拒绝是高频的——实测一次脚本化坏窗 6 秒内产生 **84,533 次** `QUEUE_OP` 重发；逐请求探测会把一次故障放大成探针风暴。 |
| T3 拒绝应答携带 Leader 地址 | 动 wire（各应答扩字段 + 版本门 + 冻结表），且 **v≤11 服务端不带地址**，兜底发现路径无论如何仍要存在——它是叠加而非替代。 |

### D3 采用规则：零生效 ∧ 从未不确定（承接先行 change）

跨会话续发仅在"本逻辑操作**从未**进入不确定窗"时允许；一旦进入不确定窗，后续明确零生效拒绝**不得**放行跨会话续发，以显式失败收场。该语义与判据由 `fix-queue-noeffect-monotonic` 确立并落规格，本 change 沿用其判据顺序、不再各自解释。

**依赖关系是硬性的**：本 change 会提高换会话频率，若先行 change 未落地，等于把"零生效逃逸"的洞带进更热的路径。

### D4 队列 `NOT_LEADER` 分支补路由重取

队列写循环在 `NOT_LEADER` 时只原地重试，而同环的瞬态与缺码形分支都重取路由。在同环内补齐该分歧（不止一处：`parkLoop` 与 `exchange` 两处均须核）。这是本 change 唯一"族内分歧收敛"性质的修改，其余族已按同环判例重取。

### D5 与 2026-10-11 判负实验的区别（必须携带的论证）

判负实验的做法：把车道的 `NOT_LEADER` 计入**共享阈值**、达阈值即**异步扇出**种子发现并重建车道——异步发现的完成撞上重发环 mid-flight，锚点 4/6 → 1/6。

本设计与它在三处正交：

1. **不接入共享阈值**（获取路径的阈值语义不变，非获取族走独立的刷新入口）；
2. **不是异步扇出后重建**：刷新是受限频、可合并的共享动作，其**结果**由请求在自己的零生效点上取用；
3. **在途请求不因结果到达而改变路由**（D1）——判负的机理（结果到达与重发环相撞）在结构上不成立。

### D6 与既有条款 4 的对账（实现前必做的核实项）

规格条款 4 的措辞（"连续 3 次业务请求收到 `NOT_LEADER` MUST 触发发现"）比实现面更宽。本 change 落地后，非获取类请求**确实**经由刷新参与了发现，但触发条件不是"连续 3 次"而是"限频 + 合并"。实现前须核实并二选一：**或**把条款 4 的措辞按实际语义收窄/移出（另立一条描述非获取族），**或**让刷新入口复用连续计数语义。倾向前者：限频本身就是防风暴的手段，比阈值更直接。核实结论必须回写规格（否则规格继续说一件实现不打算做的事）。

### D7 判据

- **主判据**：`-Pw11-repro -pl openlatch-client verify` 下两枚夹具**由红转绿**（且各自的守卫断言仍需成立：成功必须来自当值 Leader、静默错值即红）。
- **回归底线**：严格锚 `committedAtomicValueSurvivesLeaderKillWithoutDoubleApply`（活性严格）与队列锚（容忍显式失败但 MUST NOT 伪成功）逐项不变。
- **新增守卫场景**：「期望路由变更不得使在途写失败」——防回退轮重演的可执行化。

## Risks / Trade-offs

- [刷新器自身竞态] → 单飞 + 限频 + 结果发布原子化；夹具反复跑（≥3 轮）验证不 flaky。
- [D1 使换主后的写变慢或拖死] → "自身不可用"（连接死/明确拒绝）即重取；严格锚为回归底线。
- [刷新把在途请求推入失败（回退轮重演）] → D1 从结构上排除；并新增守卫场景钉住。
- [先行 change 未落地即做本 change] → D3 硬性依赖；PR 顺序上 A 先合。
- [规格条款 4 与实现长期不一致] → D6 设为实现前的必做核实项并回写规格。
- [族间采用能力不对称导致部分族仍不可收敛] → 本 change 不强行统一：无法证明零生效的族**保持显式失败**（合法终态）；是否推广零生效判定列为 Open Question。

## Migration Plan

纯客户端变更：无 proto 变更、无配置项、无数据/状态迁移。部署即随客户端产物生效；服务端零改动，升级序无窗口约束（新客户端对旧服务端按 D6/静默降级处理）。回滚＝还原客户端产物，刷新器不产生日志条目、不改服务端状态。

## Open Questions

- 是否把"零生效逃逸"（跨会话续发的许可判定）从队列推广到其余写族——本 change 不依赖它，但推广后收敛面会更宽。属可延后的判据扩展，不改本 change 的取径与任务分解。
