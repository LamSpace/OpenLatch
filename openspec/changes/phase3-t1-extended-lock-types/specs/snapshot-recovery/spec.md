## MODIFIED Requirements

### Requirement: 快照内容完整性
快照 SHALL 承载复制状态全集：全部 key 条目——锁条目（key、模式、每个 (会话,线程) 持有者的计数、租约凭证、到期时刻、生效租期）、Semaphore 条目（总许可数、可用许可数、每个 (会话,线程) 持有者的持有数与其租约）与 Latch 条目（key、初始计数、当前计数；条目存续即为已定型屏障）——与会话注册表（逻辑会话 id 集合，归属节点由其高位导出）。等待队列（锁等待者、Semaphore 等待者、Latch awaiter）与服务端本地配置 MUST NOT 进入快照。快照序列化 MUST 使用已冻结的 `SnapshotState` 消息编号，MUST NOT 变更或复用既有字段号；v3 扩展 MUST 仅以新增字段/新增条目形态表达。

#### Scenario: 快照内容清单
- **WHEN** 对含写持有、多读持有、重入计数、Semaphore 持有、Latch 计数、存活会话与历史释放空洞的状态生成快照并解析
- **THEN** 各类型条目与会话集合逐字段完整，无等待队列与本地配置痕迹

#### Scenario: 序列化确定性
- **WHEN** 同一状态在两个副本上各生成一次快照
- **THEN** 序列化字节与全量摘要逐字节一致（条目序按声明的插入序保持）

#### Scenario: 含新条目的恢复往返
- **WHEN** 节点在 Semaphore 与 Latch 状态存续时生成快照、以该快照重启并回放后续日志
- **THEN** 恢复后：许可扣减值与持有归属逐字段一致、租约到期驱动照常生效；Latch 计数与放行判定一致（归零条目恢复后 await 仍立即通过）
