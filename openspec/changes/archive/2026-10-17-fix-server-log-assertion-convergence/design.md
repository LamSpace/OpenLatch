# Design

## Context

见 `proposal.md`（动机）与台账 W23 行（现场与判定证据）。与本设计相关的现状约束：

- `ClusterHarness` 已提供两件现成工具：`awaitTrue(BooleanSupplier, timeoutMs, what)`（有界轮询）与 `aliveAgreeWithLeader()`（全存活节点摘要与 leader 一致）；后者在 `StateMachineConditionTest` 里被**裸调**，前者未被本类使用。
- `Node#lastApplied()` 读的是该节点状态机当前应用位点；副本应用是**异步**的，leader 响应返回 ≠ 全副本已应用。
- 两枚用例的断言本身是正确的（两族操作确实零日志贡献）；红的是取样时点。

## Goals / Non-Goals

**Goals:**
- 让两枚用例的**隐含前提**（取样时全员已追平）变成**显式、有界、失败可见**的前置。
- 保持断言语义与强度不变：追平后 `after == before` / `lastApplied` 与摘要零前进，任一被打破仍红。
- 消除这两枚用例作为 CI 间歇红源的资格（台账 W23 销账）。

**Non-Goals:**
- 不改产品代码，不改协议与规格。
- 不把"追平"做成无限等待：超时即断言失败（真不收敛仍在 20s 处红）。

## Decisions

**D1：用"有界等待前置"，而不是"放宽断言"。**
- 候选 A（本设计）：取样前 `awaitTrue(全员与 leader 同位点)`，断言原样保留。
- 候选 B：把断言换成"只有 leader 的位点不变"。**否决**——它丢掉了对副本的检查，属削弱；且 leader 位点在"追加已提交但尚未应用"的瞬间也不变，判据不完备。
- 候选 C：`catch` 断言失败后重试整段。**否决**——掩盖真实回归，且与"不得以重跑遮盖"的台账纪律冲突。
- 候选 D：保留裸断言、只加 sleep。**否决**——固定睡眠既慢又不构成判据。

**D2：两处等待用各自原本的判定面，不互相替换。**
- `AdminClusterTest` 断言的是逐节点 `lastApplied` 向量 ⇒ 前置等待也用 `lastApplied` 全等（以 leader 为基准，仅统计存活节点）。
- `StateMachineConditionTest` 断言的前置本就是 `aliveAgreeWithLeader()`（摘要）⇒ 直接把它包进 `awaitTrue`，语义零漂移。

**D3：等待上限取 20s（与 harness 启动期选主等待同量级）。**
- 依据：正常追平在毫秒级；20s 只用于"确实不收敛"的判负，不改变稳态时长。
- 备选：3s。**否决**——CI 2 vCPU 下冷启动/GC 抖动的余量不足，易把真收敛误判成不收敛。

## Risks / Trade-offs

- [等待把真回归推迟 20s 才暴露] → 有界且超时信息明确（`超时未满足: 基线追平`），比"偶发红在别处"更可诊断。
- [套件时长增加] → 稳态下等待第一轮即返回；实测应在毫秒级，不改变基线。
- [仍存在其他"未追平取样"形态] → 本 change 只覆盖台账 W23 登记的两枚；其余按"红一次改一处"另行登记。
