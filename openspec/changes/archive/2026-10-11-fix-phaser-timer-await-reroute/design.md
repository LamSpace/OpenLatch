# Design

## Context

动机见 `proposal.md`。塑造方案的现状与约束：

- **两族等待环与闩/屏障同型**：`deadline` 有界环 + `(route, env, envSession, rid)` 四元组 + 跨会话重建块（代码自述"纯等待无复制态副作用：跨会话重建信封安全（自愈通道）"）+ 状态分派在 `OK`/`QUEUED`（定时器另有 `DENIED`）之外**一律终态抛出**，`NOT_LEADER` 正落在该终态分支。
- **瞬态分支本就跨会话**：两族的 `ExecutionException`/换主分支已经 `route = null; env = null; continue`（新路由新会话重发）——即"结果不确定"的形态都放行了跨会话重放。
- **#22 已建立的共享机械**：`OpenLatchClient#awaitReroutedRoute(staleSessionId, deadlineMs)` 与 `NOT_LEADER_REROUTE_BUDGET_MS`（= 2 × 核对周期 = 2s）。该助手当初即为"等待类原语"通用而写，参数不含原语特有概念。
- **两族的保活护栏**：`QUEUED` 分支维持"同一会话以**原 `request_id`** 重发"（定时器侧明确写着"重挂 MUST NOT 误换 request_id（v10 真缺陷教训的护栏）"）。

## Goals / Non-Goals

**Goals:**

- 让相位器/定时器等待面与闩/屏障**族内一致**：`NOT_LEADER` 应答状态按零生效有界重道处置。
- **复用**既有助手与预算常量，不新增机制、不新增配置。

**Non-Goals:**

- 不动变异类（相位器变异车道、定时器 `schedule`/`disarm`）——其 `NOT_LEADER` 语义与等待面不同族。
- 不动不确定窗后的既有纪律；不动相位/代次语义与读数口径。

## Decisions

### D1 判据与 #22 同源，且证据更强

`NOT_LEADER` 是服务端**已答复**的拒绝 ⇒ 本次未受理 ⇒ 跨会话重放安全。两族等待环的瞬态分支**本已**放行跨会话重发，而瞬态的"可能已受理"不确定性比"已答复未受理"更强——故本条款是既有自愈通道的**收紧版**（更明确的零生效），而非放松。

### D2 复用 #22 的共享助手与预算常量

两族直接调用 `awaitReroutedRoute`，预算沿用同一常量。**备选与否决**：各族自实现 → 否决（第三、四处复制同一逻辑，且预算会出现第二处事实源）。

### D3 只改状态分派的终态分支

`QUEUED` 保活护栏与跨会话重建块**原样不动**。新分支插在"已答复 `NOT_LEADER`"这条原本直接抛出的路径上，重道成功即 `route = rerouted; continue`——由既有重建块按新会话分配新 `request_id`。

**边界（写入契约）**：跨会话重道必然换会话与 `request_id`，与"同会话保活 MUST NOT 误换 request_id"的护栏**不冲突**——那条约束的是**同一会话**内的保活重挂。两族 Javadoc 与规格均显式划清。

### D4 失败终态沿用 `NOT_LEADER`（与 #22 一致）

即使耗尽的是调用方自己的 `deadline`，也抛 `OpenLatchException(NOT_LEADER)` 而非各自的 `TimeoutException`。理由：与闩/屏障家族一致；且 `NOT_LEADER` 更精确地指向成因（无可用路由 / 未选出 Leader）。该口径已在 #22 落地并被用例锁定，本变更沿用而非另立。

### D5 相位/代次语义零触碰

重道后的重发经既有重建路径取服务端应答回显：相位器"读数恒来自服务端应答回显"、定时器"`schedule` 回执代次即观察序"两条纪律不变，客户端不本地推算相位或代次。

## Risks / Trade-offs

- [同一族分两次交付，中间态不一致] → 本变更即收口；中间态仅存在于 #22 与本变更之间，**未发布**（两者同一批次演进，未产生带该不一致的产物）。
- [误触定时器保活护栏] → 护栏约束同会话重发；跨会话重道走的是既有重建块（本已存在），本变更只增加一条**进入**该块的路径。
- [失败由"立即"变"约 2s"] → 与 #22 同款有界退化，proposal 已声明；异常仍携带可读 `NOT_LEADER`。
- [相位器等待面重道后的相位语义] → 重发取服务端回显相位（`OK{相位}`），不本地推算（D5）。

## Migration Plan

纯客户端变更：无 proto 变更、无配置项、无状态迁移。服务端零改动。回滚=还原客户端产物。
