# Design

## Context

动机与实测见 `proposal.md`。塑造方案的技术约束：

- **不能靠"取口与 bind 之间没有别人"**：探针必须关闭才能让服务端 bind，这段窗口无法消除，只能让窗口内**没有竞争者**——而竞争者正是内核的临时口分配器本身（它会把刚回收的口优先发给下一次 `connect`）。
- **不能靠重试掩盖**：服务端 bind 失败意味着整场集群装配失败（`startCluster` 抛 `IllegalStateException`），测试级重试只会把红灯变成更慢的红灯。
- **既有同款治法**：drill 侧早已踩过同一个坑并以 `b35f549` 修掉——"随机取样于 20000–29999 + `setReuseAddress(false)` + 至多 100 次换候选"。
- **环境限制**：本仓沙箱里 JVM 读到 `/proc/sys/net/ipv4/ip_local_port_range` 的内容被掩掉（实测为 `"3"`），故**判据不得依赖读 procfs**。

## Goals / Non-Goals

**Goals:**

- 让 `ClientClusterIT` 的取口不可能被同一 JVM 的并发 `connect` 抢走。
- 把"取样带是否真的在临时池之外"变成一条**显式断言**，而不是留给运气。

**Non-Goals:**

- 不动 W2 其余持有者（判例：红一次改一处）。
- 不重构 drill 侧的同款私有实现（它已验证、且属演练面；本 change 只新建共用取样器，drill 合并留待其自然接触）。
- 不改任何产品代码。

## Decisions

### D1 取样落在临时端口带之外，而不是"探到就用"

竞争者就是内核的临时口分配器；把取样带挪出临时池，等于把竞争者从窗口里**移除**。这是 drill 侧 `b35f549` 的判例，本次沿用同一带（20000–29999）。

**为什么不动态读 OS 范围来选带**：本环境下 procfs 不可读（见 Context），动态选带会让判据在 CI 与本地行为不一致；固定带 + 显式校验（D3）更诚实。

### D2 `setReuseAddress(false)` + 换候选重试

- `setReuseAddress(false)`：确保探针**真的**能绑——否则 TIME_WAIT 残留的口会被探针误判为可用（drill 侧同款）。
- 至多 100 次换候选：带内偶发占用（同机其它测试、残留绑定）不致命。

### D3 判据 OS 无关：拿"内核自动分配的口"反证取样带

不读 procfs，改为**实测内核的临时池样本**（`new ServerSocket(0)` 取样 N 次）并断言它们**不落在取样带内**。若某环境两者相交，测试立刻红——比"跑很多轮碰运气"可靠，也把策略失效从 flake 变成显式红灯。

### D4 取样器做成测试树内的共用类，而不是私有方法

`ClientClusterIT` 的私有方法无法被单测直接判定（判据要能独立跑），而这条策略在本模块已是**第二处**实现 → 收进一个包私有小类 `TestPorts`。只让红点（`ClientClusterIT`）改用它；其余持有者保持原状。

## Risks / Trade-offs

- [取样带与某环境临时池相交 ⇒ 策略失效] → D3 的断言把它变成显式红灯（而不是偶发 flake）。
- [带内 10000 个口被同机他测占用] → D2 的换候选重试兜底；探针在带内逐候选实测而非"猜"。
- [两处同款实现（drill 私有 / 本共用）] → 已知并可接受：drill 面已验证且不在本 change 范围；本 change 在记录位置列注明，避免后人误以为只有一份。

## Migration Plan

纯测试侧：无协议/配置/状态迁移；回滚＝把 `ClientClusterIT.freePort()` 还原为 `new ServerSocket(0)`。
