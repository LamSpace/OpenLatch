# Design

## Context

动机见 `proposal.md`。塑造方案的现状与约束：

- **等待环的两段式状态分派**：`RemoteCountDownLatch.doAwait` 与 `RemoteBarrier.doAwait` 都在环内维护 `(route, env, envSession, rid)`，状态分派为「`OK` 处理 / `QUEUED` 挂起等通知 / 其余一律 `throw`」。`NOT_LEADER` 落在最后一段——**虽已由服务端明确答复、却与"定型不符""队列满"等真拒绝同归终态**。
- **路由只在两处重取**：环外初取一次；环内仅在 `route == null` 与「瞬态异常」分支重取。状态分派的终态分支不重取。
- **上一轮已铺好的地基**：`OpenLatchClient` 在集群形态下按 1s（`LEADER_RECONCILE_MS`）经 `CLUSTER_VIEW` 核对当值 Leader 并改道。因此"路由陈旧"是**自愈的**，只差等待环愿意等一下并重取。
- **必须同时满足的既有判例**：`RemoteCountDownLatchScriptedTest#sameShapeNotLeaderRejectOnAwaitThrowsNotFalseGreen` 断言「显式 `OpenLatchException` **且** 耗时 < 5s」，注释写明"不悬挂至等待总预算、不假绿"；v9/D3 声明"假绿严格劣于显式失败"。
- **屏障侧的既有纪律**：`OBarrier` 契约已声明"在途 `BARRIER_AWAIT` 遇传输失败/断连/换会话 MUST NOT 自动重发（到场是有副作用的请求）"。该纪律约束的是**结果不确定**的形态。

## Goals / Non-Goals

**Goals:**

- 让"服务端已答复 `NOT_LEADER`"这一**零生效**形态可重道，从而吃掉上一轮路由收敛的地基红利。
- 保住两条既有判例关切：不假绿、失败有界（远小于等待总预算）。

**Non-Goals:**

- 不放宽**不确定窗**（传输失败/读界超时/断连）后的严格纪律——那是双插与假绿风险的来源。
- 不动相位器/定时器的同型等待面；不动变异类（发布/注册/装载/撤销）。
- 不引入配置项；不改等待位次与通知-重发语义。

## Decisions

### D1 只对"已答复的 `NOT_LEADER`"重道，不确定窗纪律原样保留

**判据**：服务端**答复** `NOT_LEADER` ⇒ 本次请求确定未受理 ⇒ 跨会话重放安全。与既有 `noEffectReject` 判例（队列的换窗重建续发）同轴：**只有"证明未生效"的形态才允许换会话重发**。

**反面**：传输失败/超时/断连属结果不确定（可能已受理），维持既有纪律（闩的严格换代守卫、屏障的到场不跨会话重放）。

**备选与否决**：把不确定窗一并放宽 → 否决。这正是 v9/D3「假绿严格劣于显式失败」要防的形态。

### D2 重道受独立短预算约束（上限 = 2 × 核对周期 = 2s）

**理由**：保住"不悬挂至等待总预算"——失败上界从 30s（等待总预算）降到 2s；而 2 个核对周期足以覆盖一次真实改道（核对周期 1s）。

**备选与否决**：
- 无条件重发至等待总预算 → 否决：推翻既有判例的偏好，且旧服务端/错配下把**快速失败**变成**慢超时**，诊断性显著变差。
- 只重试一次 → 否决：收敛窗内首次重取路由可能尚未变化，收益不可靠（首次重试往往仍打在同一陈旧路由上）。

### D3 「路由未变化」即无重道可言；预算内以既有粒度轮询等待改道

**做法**：首次收到 `NOT_LEADER` 时开启重道预算。预算内按既有 `SESSION_POLL_MS` 粒度重取路由：**路由会话变化**即以新会话重建信封重发；**始终未变**或预算耗尽 → 以 `NOT_LEADER` 显式抛出。

**理由**：重发的唯一动机是"路由陈旧"。路由不变时重发只会拿到同一个 `NOT_LEADER`——即空转。把"等待改道"显式化，也让"预算耗尽"成为可断言的终态。

### D4 只改路由，不改等待语义

重道路径只做「摘登记 → 重取路由 → 重建/重发」，不触碰 `QUEUED` 挂起、通知-重发闭环与位次语义。与上一轮 `fix-lane-reroute-convergence` 的「只收敛路由」同轴，也是它能在既有套件上零回归的原因。

### D5 预算常量单一事实源在 `OpenLatchClient`

预算 = `2 × LEADER_RECONCILE_MS`，由客户端以包私有常量暴露，两个原语共用。避免两处各自发明数字，也让周期调整时预算自动跟随。

### D6 既有用例不改断言，只同步口径注释

`sameShapeNotLeaderRejectOnAwaitThrowsNotFalseGreen` 的两条断言（显式异常、耗时 < 5s）在新行为下**依然成立**（失败发生在 2s 重道窗之后）。因此：**不新造"必须立即失败"的判例**，只把注释里"不悬挂至预算耗尽"的表述补上"有界重道窗"这一新事实。

屏障侧没有对应的既有单测（其 `NOT_LEADER` 形态此前无夹具），故新行为以新增夹具锁定。

## Risks / Trade-offs

- [永久返回 `NOT_LEADER` 的服务端/错配下失败变慢（立即 → 约 2s）] → 有界且远小于 30s 等待预算；异常仍携带可读的 `NOT_LEADER` 码。属已知有界退化（proposal 已声明）。
- [重道跨会话是否违反屏障"到场不跨会话重放"] → 不违反：该纪律约束**结果不确定**的形态；`NOT_LEADER` 已答复未受理，无到场事实可重放（D1），契约文本已显式划清边界。
- [轮询等待改道造成空转] → 仅在收到 `NOT_LEADER` 后才开启重道窗，且以既有 `SESSION_POLL_MS` 粒度；稳态零开销。
- [预算与核对周期耦合] → 预算定义为 2×周期（D5），周期调整时预算自动跟随，不会出现"预算短于一次核对"的失配。
- [相位器/定时器同型面未覆盖] → 显式非目标；已由 WATCHLIST W11 记录在案。

## Migration Plan

纯客户端变更：无 proto 变更、无配置项、无状态迁移。服务端零改动，升级序无窗口约束。回滚=还原客户端产物。
