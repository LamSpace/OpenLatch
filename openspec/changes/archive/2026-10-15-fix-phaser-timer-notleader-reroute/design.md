# Design

## Context

动机见 `proposal.md`。塑造方案的现状与约束（均为读码所得）：

- **状态分派现状**：`RemotePhaser.awaitAdvanceInterruptibly` 只认 `OK`/`QUEUED`，其余 `throw`；`RemoteTimer.awaitInterruptibly` 只认 `OK`/`DENIED`/`QUEUED`，其余 `throw`。两者的 `NOT_LEADER` 因此是终态。
- **跨会话重发对纯等待是既有语义**：两个循环在"换主/瞬态"分支上都已经写着重建信封重发（相位器：`route = null; env = null; continue`；定时器：同款），并附注释"纯等待无复制态副作用：跨会话重建信封安全（自愈通道）"。等待登记幂等、谓词在复制账簿——重挂即刻了结或续挂。
- **拒绝的语义**：服务端角色门在触达状态机前拒绝 ⇒ 那一次尝试**零生效**；应答不携带 Leader 地址（非获取类应答无提示字段）⇒ 重道必须显式触发发现。
- **触发器与预算已就位**：惰性共享刷新（单飞 + 限频 1s + 合并 + 静默降级）与等待面短预算常量（= 2×刷新周期）都已在上一轮落地，且有单一入口 `OpenLatchClient.awaitReroutedRoute(staleSessionId, deadlineMs)`。

## Goals / Non-Goals

**Goals:**

- 让"真主存在而路由陈旧"窗内的相位器/定时器**纯等待**不因零生效拒绝立即失败。
- 保持失败**有界且诚实**：预算耗尽仍显式抛 `NOT_LEADER`，绝不假绿（不返回 `true`、不返回相位号）。

**Non-Goals:**

- 不动到场半程（`arriveAndAwaitAdvance`）与变异/读数操作——见 D1。
- 不改等待语义（相位号/代次/超时归属原样）。
- 不新增安全论证：本 change 只是把既有"跨会话重挂"语义扩展到"已答复拒绝"这一入口。

## Decisions

### D1 只管纯等待：`awaitAdvance`/`awaitAdvanceInterruptibly` 与 `await`/`await(timeout)`

边界由"结果是否可判定"划死：已答复的 `NOT_LEADER` = 零生效 ⇒ 纯等待换会话重发安全（且这正是它既有的自愈纪律）。

**为什么到场半程不在内**：`arriveAndAwaitAdvance` 的 `NOT_LEADER` **不总能证明零生效**——若本次等待此前已收过 `QUEUED`（到场已记账），后来因换主/重发而收到的 `NOT_LEADER` 只说明**那一次重发**未被受理，到场本身可能已计入。此时跨会话重道会重复计次（配额归属域约束）。要做须先立"到场是否已记账"的谓词（本轮不预置结论）。

**为什么变异/读数不在内**：属"变异车道显式超时面"那条独立残余，按既有约定须逐族先立"未生效"判据。

### D2 复用既有预算与入口，不造第二套

`awaitReroutedRoute(staleSessionId, deadlineMs)` 已封装"触发刷新 + 短预算内轮询路由 + 只在会话确已变化时返回"，并已把预算常量收在 `OpenLatchClient`（= 2 × 刷新周期）。两个新等待环直接调它——**同一机制不在两处配置**（判例：门控、预算皆然）。

### D3 沿闩/屏障同款的不确定窗护栏

曾出现"结果不可判定"的失败（传输失败/读界超时/应答缺码形）的等待不再重道。对纯等待这里是**保守收窄**（其自愈通道本就允许跨会话重挂），但四条等待原语的条款因此同款同形——契约面不出现"某族多一条、某族少一条"的歧义。

### D4 零协议、零服务端、零配置

客户端本地行为修正：不改信封形态、不改服务端、不加配置项。回滚 = 还原两个等待环。

## Risks / Trade-offs

- [把"已答复拒绝"与"不确定窗"混读 → 放宽了到场纪律] → D1 只覆盖纯等待；到场半程留在原地（其既有"跨会话放弃"纪律原样）。
- [永久 `NOT_LEADER` 形态多等 2s] → 有界退化；异常仍携 `NOT_LEADER` 码（判例同闩/屏障）。
- [刷新触发叠加成探测风暴] → `RouteRefresh` 自身单飞 + 限频 + 合并，触发方只管调用。
- [与既有"分片重发/保活重挂"路径重叠] → 二者入口不同（前者是丢失唤醒后的同 id 重发，后者是零生效拒绝后的换会话重道），互不替代；D3 的护栏保证不会在不确定窗上空转 2s。

## Migration Plan

纯客户端变更：无协议/配置/状态迁移。回滚＝还原两个等待环，无残留。

## Open Questions

- `arriveAndAwaitAdvance` 到场半程的零生效重道：需要"到场是否已记账"的判据来源（客户端记账 or 服务端回显）。**故意留待另议**——它与变异车道的"未生效"判据是同一题面，宜并案立判据后再动。
