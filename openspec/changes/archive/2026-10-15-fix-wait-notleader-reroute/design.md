# Design

## Context

动机见 `proposal.md`。塑造方案的现状与约束：

- **状态分派现状**：`RemoteCountDownLatch.doAwait` 与 `RemoteBarrier.doAwait` 对 `OK`/`QUEUED` 之外的状态一律 `throw new OpenLatchException(status, …)`——`NOT_LEADER` 因此是**终态**。
- **该拒绝的语义**：服务端角色门在触达状态机前拒绝（`ClusterRequestHandler` 入口门），故**那一次尝试零生效**；应答本身**不携带** Leader 地址（非获取类应答无提示字段）——所以重道必须显式触发发现，不能指望拒绝指路。
- **触发器已就位**：`fix-lane-route-refresh` 的 `RouteRefresh`（单飞 + 限频 1s + 合并 + 静默降级）在零生效拒绝处被调用即会发布期望路由并建/换车道。**这是本 change 与回退版的唯一实质差别**：回退版只能轮询等待改道发生，本版主动促成它。
- **既有纪律（不得放宽）**：闩的换代守卫、屏障的"到场不跨会话重放"（`RemoteBarrier:215` 注释）——两者都针对**不确定窗**（应答丢失/传输失败）。已答复的 `NOT_LEADER` 不属此列（它恰恰证明未受理）。
- **回退版的设计仍可用**：`archive/2026-10-11-fix-await-notleader-reroute` 的 D1–D6（只对已答复拒绝重道 / 独立短预算 2s / 路由未变即无可重道 / 只改路由不改等待语义 / 预算常量单一事实源 / 既有用例只同步口径）逐条适用，本 change 采纳并**增补 D7（主动触发刷新）**。
- **约束**：`src/main` 其余部分零触碰；`mux`/`registry` 的既有摘除口径不变。

## Goals / Non-Goals

**Goals:**

- 让"真主存在而路由陈旧"窗内的 `await` **不立即失败**：零生效重道在短预算内完成等待。
- 保持失败**有界且诚实**：预算耗尽仍显式抛 `NOT_LEADER`，绝不假绿。

**Non-Goals:**

- 不改等待语义（位次/世代/超时归属原样）。
- 不放宽不确定窗纪律。
- 不做相位器/定时器等待面（同型但另议：其"已到场/已装载"的事实面更重，需单独判据）。
- 不做变异类（`NOT_LEADER` 对它们是"可能已受理"的信号）。

## Decisions

### D1 只对"已答复的 `NOT_LEADER`"重道；不确定窗纪律原样保留

边界即语义：**已答复**（服务端说了 `NOT_LEADER`）= 零生效 ⇒ 可重道；**未答复**（超时/传输失败/断连）= 不确定窗 ⇒ 照旧严格放弃（闩的换代守卫、屏障的不跨会话重放）。这条边界是本设计成立的全部依据。

### D2 重道受独立短预算约束（上限 = 2s）

与调用方等待总预算**无关**：确保"永久 `NOT_LEADER`"形态的失败由"立即"退化为"有界 2s"，而非悬挂至总预算（判例：回退版 D2，理由未变）。

### D3 路由未变化即无可重道

预算内以既有粒度轮询"路由会话是否已变"；未变 → 无重道可言，到点显式抛出。避免在无改道可能的窗口内空转。

### D4 主动触发刷新（本 change 相对回退版的新增）

重道开始时**调用 `client.requestRouteRefresh()`**——即"本方路由陈旧"这一事实本身就是刷新的合法触发点（明确零生效拒绝）。回退版仅被动轮询等待改道；在有触发器之后，被动等待会把收敛延迟不可控地压在刷新周期上。

### D5 只改路由，不改等待语义

重发沿用既有重挂/重发纪律（同 `request_id` 幂等口径按各族既有裁决），不改位次与超时归属。

### D6 预算常量单一事实源

短预算取 `OpenLatchClient` 的刷新周期常量派生（`2 × ROUTE_REFRESH_MIN_INTERVAL_MS`），不新造魔法数——避免"改了一处忘了另一处"。

### D7 既有用例只同步口径注释

`sameShapeNotLeaderRejectOnAwaitThrowsNotFalseGreen` 的**断言不变**（显式异常 + 耗时上界），仅注释说明"重道在下述条件下可能先行成功"。

## Risks / Trade-offs

- [把"已答复拒绝"与"不确定窗"混读 → 放宽了不该放宽的纪律] → D1 划死边界；既有守卫用例（闩换代 / 屏障不跨会话重放）为回归底线且断言不变。
- [永久 `NOT_LEADER` 形态多等 2s] → 有界退化，D2 明确；异常仍携 `NOT_LEADER` 码。
- [刷新触发叠加成探测风暴] → `RouteRefresh` 自身单飞 + 限频 + 合并，触发方只管调用。
- [重道与既有重挂路径重复] → D5：沿用既有纪律，不新造重发路径。

## Migration Plan

纯客户端变更：无协议/配置/状态迁移。回滚＝还原两个等待环，无残留。

## Open Questions

- 相位器/定时器等待面（`awaitAdvance`/`AWAIT`）是否适用同一形态——**故意留待另议**：它们的"已到场/已装载"事实与闩/屏障不同，需各自的判据与夹具；本 change 不预判结论。
