# Design

## Context

动机见 proposal.md - Why，不重复。此处只沉淀决定方案的现状约束（实测）。

- `ROADMAP.md` 当前身兼三职：**演进路线表**（一档/二档/三档/工程改进四表 + 状态图例，全部"已落地"或已退役）+ **决策记录**（活账本）+ **不做清单 / 每原语落地纪律**（活治理）。
- **活引用面**（`grep`，排除归档）：`openspec/specs/replicated-state-machine/spec.md` **×4** 条常驻守卫（正文"改动本条款 MUST 先经 ROADMAP 决策记录登记"）；`WATCHLIST.md` **W5** ×2 处（现状列与记录位置列各一）。
- **历史引用面**：约 30 个 `openspec/changes/archive/**` 的 ROADMAP 引用——记当时为真。
- **文件内自引用**：决策记录中第三项裁决行含"第 52 行原…"（指向路线图表行号）；维护规约整节均在描述"路线图表"的维护方式。

## Goals / Non-Goals

**Goals**

- 把"演进路线（已死）"与"决策账本（活）"分离：剥离死表、保全治理资产。
- 让 durable spec 的规范性引用有活的目标（`DECISIONS.md`）。
- 保留文件历史（`git mv`，非删除+新建）。

**Non-Goals**

- 不改任何行为 / API / 协议；不重写历史决策内容。
- 不保留状态图例与四张路线图表（其信息已沉淀在归档 change 与规格）。
- 不触归档 change 的历史引用（记当时为真）。

## Decisions

**D1 改名而非删除。**
理由：`replicated-state-machine` 四条守卫**规范性引用**"决策记录"，删除即令其悬空且失去登记处。**替代**：物理删除——否决（spec ×4 破链，守卫立法闭环失效）。

**D2 剥死表、保治理。**
删除"状态图例"节与一档/二档/三档/工程改进四表；**保留**决策记录、不做清单、每原语落地纪律。信息无损——路线图表的原语细节已在各自归档 change 与 specs。

**D3 文件头重定位。**
标题 `# 演进路线(Roadmap)` → `# 决策账本(Decision Ledger)`；导语（"本表是主动演进方向与次序的决策清单…"）重写为账本定位 + 与 `WATCHLIST` 的分工；"最后更新"改为 2026-10-10。

**D4 活引用改写（承接规格 delta）。**
`spec` ×4："改动本条款 MUST 先经 ROADMAP 决策记录登记" → "…先经 DECISIONS.md 决策记录登记"；`WATCHLIST` W5 ×2 同款。这是本 change 的 **MODIFIED spec delta** 的实质——四条守卫条款文本更名，断言的编号项与全部场景逐字不变。

**D5 历史决策条目冻结，不自引用改写。**
决策记录为**追加式历史账本**——已落行的历史裁决逐字保留（含第三项裁决行内的"第 52 行原…"行号锚：记当时为真）。仅改写**描述文件自身运作方式**的维护规约节（"本表/表格/分工"措辞随表移除据实校正）。**替代**：回改历史条目——否决（重写账本历史，破坏账本可信性）。

**D6 维护规约重写为"账本维护规约"。**
原四条的"更新本表状态/再动表格/本表=主动方向"随路线图表移除而失效，重写为：决策记录追加式、定位边界变更先补决策行、与 WATCHLIST 分工（WATCHLIST=被动触发观察，本文件=主动裁决）、本文件不写长文。

## Risks / Trade-offs

- [改名后归档 change 的 ROADMAP 引用变为"指向旧名"的历史引用] → 有意保留（D5）；归档是历史档案，记当时为真。
- [MODIFIED delta 场景被漏抄致 validate 拒] → 四条守卫**全量**逐字复制（含全部 `#### Scenario`）；写完 `--strict` 自检。
- [维护规约重写引入语义漂移] → 只做"随表移除的据实校正"，不新增规约。

## Migration Plan

治理文档改名随本 change 落地，无部署/回滚（无代码、无数据、无协议）。回滚 = `git mv DECISIONS.md ROADMAP.md` + 还原引用改写。
