# Proposal

## Why

ROADMAP 三档候选原语"延时触发（定时单次标记）"（JDK `Timer` 对应）现行裁决为"由 `OBlockingQueue` 延时形态覆盖即可，不单立"。经语义矩阵核验，该覆盖结论只对一半：延时形态承载的是**延时交接**（一元素恰一消费者、到期即入可见集），而 `Timer` 的另一半语义——**到期后全体观察者共见同一标记**（N 等待者共见一次到期，队列需 N 元素且首个消费者即改变所有人可观测状态）与**到期前改期/撤销**（队列无"撤回落未到的那个元素"通道）——不可表达。用户据此裁决按 OCondition/OPhaser 先例提前立项复刻（2026-10-06，放行依据在 ROADMAP 决策记录登记，第 43 行"覆盖即可"结论随本提案收窄为如实表述），并将第 43 行"挂起"与"已随 v7 落地兑现"的语义打架一并收口。技术上该原语的全部机制先例就位：延时可见性判定的"到期是可见性判定而非复制状态迁移"公式（v7 就绪驱动原文）、绝对到期时刻"随复制日志确定化、Leader 切换与副本回放不改判"（v7 队列判例）、等待分片保活重挂"谓词在复制账簿跨换主无损自愈"（v10 论证）、到期扫描驱动的当选首扫补偿（v3 租约驱动判例）。它是三档中语义保真成本最低的立项：**fire 是复制账簿与钟的纯函数**——装载/撤销进日志、到期零条目、等待是订阅。

## What Changes

- 协议升至 **v11 门**：`MessageType` 新增 `TIMER_OP = 23` 单一消息对（`TimerOp` 五操作词表 `SCHEDULE / DISARM / AWAIT / CANCEL / QUERY`——装载、撤销、等待、撤销等待、读数；AWAIT 为阻塞位操作词承载，判例 v7 `take` 与 v10 `AWAIT_ADVANCE` 折叠）；`LockType` 新增 `LOCK_TYPE_TIMER = 15`（定型判别，**开新家族 `KeyFamily.TIMER` 与新条目类 `TimerEntry`**）；`RaftEntryType` 新增 `TIMER_OP_ENTRY = 15`——v10 的"止于 14"编号证据线就此更替为"止于 15、15 为 timer 专用"（守卫基线随本提案同轮升至 15，既有"止于 14"各守卫改版本相对口径）；`Envelope.payload` 槽 49/50；`StatusCode` **零新增**（delay 越界骑 `INVALID_REQUEST`——租约越界判例；等待深度超限骑 `OVERLOADED`——v7/v9/v10 轨判例；`DENIED` 首次作 timer AWAIT 的"当代已撤销装载、等待不可满足"终态回执——既有值新可达面，非新枚）。握手三处常量 10→11（`OpenLatchServer.PROTOCOL_VERSION`、客户端 `ConnectionManager`/`RequestMultiplexer`）；v≤10 会话携带 `TIMER_OP` → `INVALID_REQUEST` 消息级拒绝、不断连（判例 v3–v10 门）。
- **到期派生裁决（本提案核心分岔，design D1 承载论据）**：复制账簿仅存 `{generation, armed, fire_at_ms, 每会话装载去重槽}`；SCHEDULE/DISARM 每一变异恰一条 `TIMER_OP_ENTRY`（装载是状态迁移——沿 v5/v10"迁移入日志"纪律，落地纪律第 2 条对本原语**不豁免**）；**到期（fire）零日志、零条目**——`marked = armed ∧ 判定时刻 ≥ fire_at_ms` 是复制数据与钟的纯函数，"到期不是迁移，是时间的兑现"（v7 就绪驱动"到期是可见性判定而非复制状态迁移"公式的类目化，与 v3 租约到期"到期是状态迁移故入日志"构成判例族两端）；AWAIT/CANCEL/QUERY 零日志 Leader 本地（"等待是订阅不是状态"与"观察不是迁移"两判例族直接延伸）。绝对到期时刻在 SCHEDULE 条目的**应用点**由条目携带时刻折算（v7 队列延时形态判例逐字适用——Leader 切换与副本回放不改判，跨副本 digest 恒逐字节一致，因 digest 面上根本没有 fire 事件）。
- **core 新建 `TimerEntry` + `KeyFamily.TIMER`**：账簿 = 代次号（装载次数，自 1 起单调递增、不取模、重启/换主不回退）+ 装载态（`PENDING@fire_at_ms` / `DISARMED` 当代终结，代内粘滞）+ 每会话装载去重槽（单槽 `{request_id, op, 回执回声}`，判例 v7 队列交付槽）。合拢判据即到期判据：`PENDING ∧ now ≥ fire_at_ms`。语义要点：①**单次**——一次装载恰一发，到期后标记粘滞全员共见，"再来一次"= 重新 SCHEDULE（换代清钟，`marked` 归伪）；②**改期即换代**——在等旁观者以最新代为准（契约声明，等待方超时自救兜底）；③`DISARM` 为代终结并**事件驱动即时唤醒全体在等旁观者以 `DENIED` 终态了结**（到期唤醒靠钟、撤销唤醒靠事件，两类唤醒源复用同一 `AWAIT_NOTIFY`）；④条目定型：SCHEDULE 在无条目时创建（判例 v5/v10 首建定型），其余操作命中不存在条目 → `INVALID_REQUEST`（无隐式建条目）；条目存续不回收（v5 D9 判例，maxKeys 兜底）。
- **死亡语义（与 v10 刻意对照的第三种形态）**：`SESSION_CLOSE` 对 timer 账簿**零扰动**——触发绑定 key 不绑会话，**创建者死亡钟照响**（队列"死亡不吞元素"同轴，正是本原语相对客户端本地 `Timer` 的存在价值）；其等待位按 (会话) 摘除（订阅层随会话灭，判例 phaser 等待摘除）。与 Barrier"死亡即破障"、Phaser"死亡=隐式摘除配额"并列成死亡语义三形态对照表（规格/Javadoc/指南三处呈现）。**增强声明**：读数 `marked` 的判定时刻取判定发生节点的本地时钟（Leader 应答面），Follower 管理面呈现原始 `{generation, armed, fire_at_ms}` 不做折算——跨节点可见性偏差 ≤ 节点间时钟偏移，为显式语义降级条款。
- **三个 Non-Goal（design D9）**：①周期重挂（`Timer.schedule(task, delay, period)`）不做——服务端周期自触即常驻重发变异，正是条目率治理最惧形态；客户端循环 `schedule` 即等价，与"fire 零条目"裁决同轴（服务端永不自写日志）。②任务载荷/回调不做——服务端不执行用户代码（v10 D4 onAdvance 同轴论证）。③绝对时刻装载（`scheduleAt(epochMs)`）不收——客户端墙钟偏差直接注入账簿即污染判据，仅收相对延迟（v7 `offerDelayed` 同款入参纪律）。另：一 key 一钟（代次互斥，无多闹钟并存/优先级堆，KeyedTimer 形态不采）。
- server 面：新建 `TimerReadyDriver`（判例 `QueueReadyDriver` 逐件同型：Leader 角色短路、当选立即首扫补偿换任窗漏扫、单守护线程固定周期、MUST NOT 提交任何日志条目；唤醒=对"有挂起等待者且 `PENDING ∧ now ≥ fire_at`"的 key 全员推 `AWAIT_NOTIFY`，误唤醒由回执重评谓词自愈）。新配置两枚：`max-timer-horizon-ms`（`openlatch.server.timer.max-horizon-ms`，默认 86400000（24h）、合法域 [1000, 604800000]——装载入带钳制，越界 `INVALID_REQUEST`，判例 lease 钳制）与 `timer-ready-tick-ms`（`openlatch.server.timer.ready-tick-ms`，默认 200、MUST ≥10——与队列 tick 分轨防耦合调参，唤醒精度恒为 tick 级契约句沿 ODelayQueue 先例）；timer 等待项与锁/Latch/条件/phaser 等待**合并计数**受 `max-queue-depth-per-key` 护栏（v9/v10 判例，超限 `OVERLOADED`）；Follower 对五操作词全量同型 `NOT_LEADER` 零副作用（直发车道判例族）。
- 管理面/控制台/指标纯增量：`family` 词表增 `TIMER`；LIST_KEYS/KEY_DETAIL 续接编号增 timer 读数（`AdminKeyInfo` 自 22 起：`timer_generation`/`timer_armed`/`timer_fire_at_ms`；`AdminKeyDetailResponse` 同三计数 + `repeated AdminTimerWaiterInfo {session_id, request_id, armed_at_ms}` 等待明细；`AdminSummaryResponse` 续接 `timer_entries`）；**账簿三读数为复制态、各节点一致**（与 phaser 账簿同轨、与 topic 本地表分轨），等待明细 Leader-only 如实零（双速呈现延伸——timer 的差异在"读数不做 marked 折算"，原始 fireAt 呈现无时钟歧义）；无载荷外发面（纯计数与时刻）；控制台三页扩 timer 区段；指标新命名点 `openlatch.server.timer.total{op,status}` 与 `openlatch.server.timer.fired.total`（Leader 到期唤醒事件计数，驱动扫描到点且有在等者时按 key 计一次——`waiters`/`fired` 两面观察 armed 存量经管理面 `timer_entries`+KEY_DETAIL 读数承载，timer 单键装载态二值、不设单键峰值 Gauge，与"五口径"之辨补注记防混读）；`waiters` Gauge 与 SUMMARY 等待者总数**计入** timer 等待项（v9"等待就是等待"合并口径再延伸）。
- 客户端 SDK：`OTimer` 公开契约 + `OClient.newTimer(key)` 工厂（句柄构造零网络、无初始装载参数——装载是显式操作，对照 `newPhaser(initialParties)` 无注册即无应到的构造红利）；API 面 `schedule(long delay, TimeUnit)`（回显代次）/ `disarm()` / `await()` / `await(long timeout, TimeUnit)`（`true`=见到当代标记；`false`=超时；当代被撤销 → `OpenLatchException`——"等待不可满足"为异常终态而非布尔混读）/ `isFired()` / `isArmed()` / `getRemainingMillis()`（advisory 读数，Leader 本地判定，即刻过期是契约）；接口级 Javadoc 全量降级/增强/保真三清单（无周期、无任务执行、无绝对时刻、改期以最新代为准、死亡不撤钟的增强声明、钟偏移可见性降级、每操作 RTT 成本模型）；直发车道 + 等待分片保活重挂（谓词在复制账簿跨换主无损自愈——v10 论证逐件复用，**同-rid 重发回归用例同轮必备**，v10 过程真缺陷教训）；超时/中断 → `CANCEL` fire-and-forget（判例 v9/v10）；握手常量升 11。
- **守卫回归（常驻条款）**：复制边界断言入 `replicated-state-machine`——纯 timer 流量下 SCHEDULE/DISARM 每变异恰一条 `TIMER_OP_ENTRY`、AWAIT/CANCEL/QUERY 零条目、**时钟走过到期点后日志恒零新增**（派生裁决的常驻守卫，与"等待误入日志即红"对偶：**"到期误入日志即红"**）、三副本 digest 逐字节（含到期后查询窗口）、重启/回放装载去重槽命中不双换代、换主等待集清零重挂了结无损耗、编号证据基线 14→15 更替双代对照；快照扩维断言入 `snapshot-recovery`（`SnapshotLock` 自 42 起 timer 字段全量往返、等待集零足迹对偶构造字节等、尺寸由常数+槽行钳制有界——timer 是持久态原语，回滚口径沿屏障/队列/phaser 型）。`RejectCodecTableTest` 扩 TIMER_OP 同型拒绝行（W10 判例常驻）。
- 测试：`TimerEntryTest` 判定矩阵（换代清钟/粘滞共见/DISARM 终态与 DENIED 了结/到期前后谓词三态/去重重放单换代/无条目拒绝/零延迟即刻共见/恢复往返/导出确定性）；`CoreEngineTimerTest` 单机门面；`TimerGatingTest`（v≤10 消息级拒绝不断连 + 五操作形状互斥矩阵（SCHEDULE 必携 `delay_ms ∈ [0, horizon]`、`CANCEL` 必携 `await_request_id`、余者对应字段 0）+ horizon 钳制 + 撞 key 家族互拒 + QUERY 形状）；`ClusterTimerTest` E2E（一到多等待者同刻齐过矩阵、**kill 装载者进程钟照响**——头号验收点（对标 Barrier 破障/Phaser 摘除的死亡 E2E 形态）、改期续睡/提前先响、DISARM 唤醒 DENIED、换主账簿存续+重挂了结+首扫补偿到期存量、同 request_id 重发单换代、Follower 五操作词零副作用、并发装载/到期竞态）；`StateMachineTimerTest`（复制边界守卫族）；客户端 Scripted + `ClientTimerIT`；协议冻结扩 v11 全量编号表 + presence 形态 codec 往返；`FairOrderingSuite` 豁免登记（判例 v5 D6/v10：AWAIT 是广播谓词等待非队首批授，无 FIFO 授予序）；config/vocabulary/控制台/快照夹具扩 timer 维；换主类断言一律"有界总超时 + eventually"形态（v9 D12 纪律）；集群重测试并入共享 harness、守 fork 端口纪律（W2 判例）。

## Capabilities

### New Capabilities

### Modified Capabilities

- `wire-protocol`: v11 门与握手常量三处；`TIMER_OP` 消息对与五操作词表（AWAIT 阻塞位折叠、形状互斥矩阵、家族违例）；`LOCK_TYPE_TIMER=15`/`TIMER_OP_ENTRY=15` 编号落位与"止于 14"证据线更替条款（新证据线：`StatusCode` 止于 13 零新增、`LockType` 止于 15、`RaftEntryType` 止于 15）；`DENIED` 对 timer 的可达性声明；horizon 越界骑 `INVALID_REQUEST` 的零新增条款；管理面 timer 字段续接；既有 v10 增量条款的编号证据改版本相对口径。
- `core-lock-engine`: `TimerEntry` 时钟谓词账簿状态机——装载代次单调、`PENDING@fire_at_ms`/`DISARMED` 两态、到期判定为账簿与判定时刻的纯函数、改期换代清钟、DISARM 事件驱动 `DENIED` 了结、装载去重槽单槽幂等、无条目拒绝、条目存续不回收、`restored` 恢复往返、SESSION_CLOSE 对账簿零扰动（与 phaser 摘除、barrier 破障三形态对照）；家族定型表增 TIMER。
- `lock-server`: v11 门控（v≤10 会话 `TIMER_OP` 消息级拒绝不断连）；SCHEDULE/DISARM Leader 提交与 AWAIT/CANCEL/QUERY Leader 本地直受理、Follower 同型 `NOT_LEADER` 零副作用；`TimerReadyDriver` 到期唤醒（零日志、当选首扫、tick 精度契约句）；`max-timer-horizon-ms`/`timer-ready-tick-ms` 两配置与启动日志；合并深度护栏（timer 等待计 `max-queue-depth-per-key`）；结果→状态码映射（`OVERLOADED` 深度线、`INVALID_REQUEST` 形状/越界/无条目线、`DENIED` 撤销终态线）；三路等待回收接线（CANCEL/`closeSession` 摘除/换主清零）。
- `replicated-state-machine`: timer 复制边界——每变异恰一条 `TIMER_OP_ENTRY`、等待/取消/查询零条目、**到期零条目常驻守卫（时钟走过到期点日志恒零新增）**、apply 确定性与跨副本 digest 逐字节（绝对到期时刻应用点折算、回放不改判）、装载去重槽重放不双换代、编号证据基线 14→15 更替的常驻守卫条款。
- `snapshot-recovery`: `SnapshotLock` timer 字段扩维（代次、装载态、绝对到期时刻、每会话装载去重槽）与逐字段恢复保真；等待集零快照足迹（同账簿终态不同等待集构造字节等）；timer 条目尺寸有界断言；持久态原语回滚口径延续条款（对照 topic/condition 零足迹分轨）。
- `client-sdk`: `OTimer` 公开契约（降级/增强/保真三清单：无周期/无任务执行/无绝对时刻、改期最新代为准、死亡不撤钟增强、钟偏移可见性降级、查询非实时一致）、`newTimer` 工厂与装载代次回显、直发车道与等待挂起-通知-重发闭环、双通道自动重挂、超时 CANCEL 纪律、握手升 11。
- `admin-observability`: LIST_KEYS/KEY_DETAIL timer 读数（代次/装载态/绝对到期时刻三计数——复制态各节点一致 + 等待明细 Leader-only 如实零）；`waiters` 合计口径计入 timer 等待项；**读数不做 marked 折算**（原始 fireAt 呈现，无时钟歧义）；观察零扰动延伸。

- **openlatch-protocol**：`openlatch.proto` 纯增量（`MessageType.TIMER_OP=23`、`TimerOp` 枚举、`TimerOpRequest/Response`、`Envelope.payload` 槽 49/50、`LockType` 15、管理面 timer 字段）；`raft.proto` 仅三处增量（`RaftEntryType.TIMER_OP_ENTRY=15`、`SnapshotLock` 自 42 起 timer 字段、`ApplyResult` 自 27 起回执三元组——应用点折算终值经回执取回，判例 phaser 回执族）；契约冻结测试扩 v11 全量编号表；`ProtocolCodecTest` 扩 presence 形态往返。
