# Proposal

## Why

ROADMAP 三档候选原语 `OPhaser`（JDK `Phaser` 对应，"Barrier 的泛化（动态注册/分层派生），Barrier 落地后自然延伸"）经用户裁决提前立项复刻（2026-10-06，需求信号未至、以预研立项完善契约设计——放行依据按 2026-10-05 OCondition 同款在 ROADMAP 决策记录登记）。技术上该原语的全部机制先例已就位：Barrier 的"到场是状态迁移、全量进日志"与复制侧账簿+了结记录切分（v5）、队列的每会话去重槽与阻塞位折叠（v7）、条件的等待三路回收、事件驱动零新定时器与合并深度护栏（v9）、topic 的双通道自动重挂（v8）。它是 v8 以来第二个**不开辟任何新基建**的协调原语：无新推送类型（骑 `AWAIT_NOTIFY`）、无新 registry（等待项住 `PhaserEntry`）、无新驱动定时器。其"相位等待是纯复制态谓词"形态补齐等待叙事三分层的最后一块——Latch/Barrier 的等待随世代破局、Condition 的等待是事件窗无自愈（signal 灭失，W13）、**Phaser 的等待可跨换主无损自愈**——与 v9 恰成对照的增强声明，是三档中语义保真与架构收益比最高的一项。

## What Changes

- 协议升至 **v10 门**：`MessageType` 新增 `PHASER_OP = 22` 单一消息对（`PhaserOp` 七操作词表 `REGISTER / ARRIVE / ARRIVE_AND_AWAIT / ARRIVE_AND_DEREGISTER / AWAIT_ADVANCE / CANCEL / QUERY`；`bulkRegister` 折叠为 REGISTER 携带 count、阻塞位折叠判例 v7 `put/offer` 与 `take/poll`）；`LockType` 新增 `LOCK_TYPE_PHASER = 14`（定型判别，**开新家族 `KeyFamily.PHASER` 与新条目类 `PhaserEntry`**——对照 topic/condition 零 LockType 判例：phaser 有复制态账簿需要条目承载）；`RaftEntryType` 新增 `PHASER_OP_ENTRY = 14`——**v8/v9 两代"RaftEntryType 止于 13"编号证据线就此更替**，守卫基线（`StateMachineTopicTest` 等编号证据断言）随本提案同轮升至 14，更替本身登记为常驻回归断言；`Envelope.payload` 槽 47/48；`StatusCode` **零新增**（parties 上限骑 `OVERLOADED`——v7"等待满"轨判例；core 内部 `Outcome.REJECT_PHASER_PARTIES` 承载细分，对照 v8 `REJECT_SUBSCRIBERS` 立枚分岔的理由在 design 记载）。握手三处常量 9→10（`OpenLatchServer.PROTOCOL_VERSION`、客户端 `ConnectionManager`/`RequestMultiplexer`）；v≤9 会话携带 `PHASER_OP` → `INVALID_REQUEST` 消息级拒绝、不断连（判例 v3–v9 门）。
- **全入日志裁决（本提案核心分岔，design 承载论据）**：四个变异操作（REGISTER/ARRIVE/ARRIVE_AND_AWAIT 的到场半程/ARRIVE_AND_DEREGISTER）**每一变异恰一条 `PHASER_OP_ENTRY`**——注册配额、到场计数、相位推进全是决定后续合拢的复制态迁移（沿 v5 Barrier"到场是状态迁移"，与 Latch"计数进、等待不入"同族）；**AWAIT_ADVANCE/CANCEL/QUERY 零日志**——等待登记与取消是 Leader 本地承诺（"等待不入日志"v3/v5/v7 判例族的又一类目：**等待是订阅不是状态**），查询是 Leader 本地读数。落地纪律第 2 条（core 条目 + Raft 命令路径）对本原语**不豁免**（与 v8/v9 的豁免类目化相对，本行即编号与路径的对照证据）。双拓扑落位（判例 v9 D1）：变异操作 Leader 提交、apply 点同关键区内执行账簿变更与合拢判定唤醒广播；AWAIT_ADVANCE 恒 Leader 受理点本地登记即回执（`QUEUED`），不提交——Follower 收到任何 `PHASER_OP` → 同型 `NOT_LEADER` 拒绝零副作用（判例 QUEUE/TOPIC/CONDITION 直发车道）。
- **core 新建 `PhaserEntry` + `KeyFamily.PHASER`**：复制侧账簿 = 相位号（自 0 起单调递增、不取模、重启/换主不回退）+ `registeredParties` 总数 + **每会话注册配额**（死亡清扫与 `arriveAndDeregister` 扣减归属的依据）+ 当前相位 `arrived` 计数 + `(session, request_id)` 到场去重槽（同请求重发单计数，判例 v7 每会话去重槽/v5 到场账簿）+ 有界了结记录（仅保最近一次相位推进的已通知未重发等待项集，窗口下界 `headReplyTimeoutMs` 压住——v5 D7 同款）。合拢规则：`arrived ≥ registered` → 同关键区 `phase++`、`arrived` 清零、按 `observed_phase < 新相位` 全员唤醒广播（事件驱动，**零新定时器、零新驱动**，v9 D7 同相）。条目定型：REGISTER 在无条目时创建（v3 `permits_total` 先例），其余操作命中不存在条目 → `INVALID_REQUEST`（phaser 无"非零主张定型"可折叠，不做隐式建条目，避免"key 在而账簿空"歧义窗）；条目定型后**存续不回收**（v5 D9 判例：key 即 phaser 身份、相位单调依赖条目存续，常驻由 maxKeys 兜底）。
- **死亡语义（用户裁决③，本原语对 Barrier 的最大泛化兑现）**：`SESSION_CLOSE` apply → 该会话全部注册配额**隐式摘除**（`registered -= Σ配额`、配额账簿删除；**已到场事实不撤销**——已计入 `arrived` 的不回退，与 v7"死亡不吞元素"对偶：发生过的计数是事实）；摘除后若 `arrived ≥ registered` 且存在存活等待项，该 apply 点即合拢推进并唤醒——**单死者不炸一锅，无破相**。registered 摘除归零 = 空转不终止（见下条终止裁决），后续 REGISTER 自当前相位复活运转。等待集按 (会话) 摘除（Leader 易失，`closeSession` 家族钩子沿用）。与 Barrier"死亡→即时破障"的差异是**契约显式声明条款**（动态成员性正是 Phaser 泛化 Barrier 的核心增量，规格/Javadoc/指南三处对照呈现）。
- **三个 Non-Goal（用户裁决②：砍 onAdvance 钩子、砍终止态粘滞、砍父子分层派生）**：①`onAdvance` 钩子不做——服务端无法执行用户代码；v5 D3"执行者回报两阶段"判例显式不采纳：相位合拢是高频级联事件，每相位挂账一跳 RTT 且执行者死亡需破账治理，成本放大而收益（动作先于推进可见）在分布式下本不可保真；应用侧以 `arriveAndAwaitAdvance()` 返回的到场相位号判别自行动作，与 JDK"动作先于全体放行"的差异入降级清单。②终止态（`terminated` 粘滞）不做——无钩子即无终止来源；"注册归零即终止"否决：v5 D4 拒绝粘滞破障的同一论证（一批死者卡死后续无辜参与者）在跨进程共享 key 下更成立；`isTerminated()`/`forceTerminated()` 不入 SDK 面，与 JDK 差异登记。③父子分层派生不做——JDK 分层是千级 party 本地计数器的可扩展性优化，分布式下每到场一次 RTT、红利在 RTT 瓶颈前消失（与 ROADMAP 不做清单 LongAdder 行同轴论证）；一 key 一 phaser，`parent` 参数不收。
- **查询线性化降级（用户裁决④）**：`PHASER_OP.QUERY`（回 `phase`/`registered`/`arrived`/`unarrived` 四计数）为 **Leader 本地只读、零日志**（判例 v8 撞 key 只读探测），与 v4 ATOMIC `GET`"读亦全量经提交"判例**刻意不一致**并三处声明（规格/Javadoc/指南）——论据：ATOMIC 读值是 CAS 序列的参与者需线性化，phaser 相位读数本质是 advisory 观察（JDK `getPhase()` 同款，调用后立即过期是语言事实），免日志同时把 W14 型条目率暴露面砍到只剩变异。
- **等待闭环与重挂（v10 契约分层卖点）**：`QUEUED → AWAIT_NOTIFY(ref = 等待项 request_id) → 原 request_id 重发命中了结记录 → OK{相位回显}` 全套复用 v3/v5 纪律，**零新推送类型**；超时 = 客户端本地计时 + `CANCEL` fire-and-forget（判例 v9 LEAVE），三路回收（CANCEL/会话死亡/换主清零）+ `headReplyTimeoutMs` 清扫兜底已通知未重发 ghost；**换主后重挂无损耗**——等待是纯复制态谓词，重挂 `AWAIT_ADVANCE(observed_phase)` 命中当值账簿：已推进即刻了结、未推进续挂（对照 v9"signal 是事件、换主窗灭失不补偿"（W13），本原语等待具自愈通道，为**增强声明**）；重挂通道复用 v8 双通道（车道激活事件 + 周期保活）。`ARRIVE_AND_AWAIT` 的到场半程经日志、等待半程本地登记——同一条目请求携带，回执合一（合拢恰由本次到场触达时直接 `OK`，不发生等待）。
- 配置与护栏：新增 `max-parties-per-phaser`（默认 1024、合法域 [1,65536]，判例 `max-queue-capacity`/`max-subscribers-per-key`）+ 启动日志扩展；`REGISTER` 使 registered 超上限 → 在带拒绝（`OVERLOADED`，既有订阅零扰动——判例 REJECT_SUBSCRIBERS 形态骑现成码）；等待项与锁/Latch/条件等待**合并计数**受 `max-queue-depth-per-key` 护栏（v9 D7 判例，超限 `OVERLOADED`）；除此之外零新配置、零新定时器。
- 管理面/控制台/指标纯增量：`family` 词表增 `PHASER`；LIST_KEYS/KEY_DETAIL 续接编号增 phaser 读数（`AdminKeyInfo` 自 19 起：`phaser_phase`/`phaser_registered`/`phaser_arrived`；`AdminKeyDetailResponse` 自 33 起：同计数 + `repeated AdminPhaserWaiterInfo {session_id, request_id, observed_phase, registered_at_ms}` 等待明细 + `repeated AdminPhaserPartyInfo {session_id, parties}` 配额明细；Leader-only 口径挂既有 `wait_queue_leader_only` 同源标志，Follower 如实零读）；**无载荷外发面**（纯计数与身份，v6 防放大纪律天然满足）；控制台三页扩 phaser 区段；指标新命名点 `openlatch.server.phaser.total{op,status}` 与 `openlatch.server.phaser.parties.registered.max`（抓取时刻单键注册峰值；**四口径注释互引条款扩为五口径**——`queue.depth.max`/`elements.depth.max`/`topic.subscribers.max`/`condition.waiters.max`/`phaser.parties.registered.max`）；`waiters` Gauge 与 SUMMARY 等待者总数**计入** phaser 等待项（v9"等待就是等待"合并口径延伸）。
- 客户端 SDK：`OPhaser` 公开契约 + `OClient.newPhaser(key)` / `newPhaser(key, initialParties)` 工厂（句柄构造零网络；`initialParties > 0` 时首次操作前同步提交 `REGISTER(count)` 归属本会话——JDK `new Phaser(n)` 同型；register/bulkRegister 均按调用会话记账）；API 面 `register()` / `bulkRegister(int)` / `arrive()` / `arriveAndDeregister()` / `arriveAndAwaitAdvance()` / `awaitAdvance(int)` / `awaitAdvanceInterruptibly(int, timeout, unit)` / `getPhase()` / `getRegisteredParties()` / `getArrivedParties()` / `getUnarrivedParties()`；接口级 Javadoc 全量降级/增强/保真三清单（**配额归属严格化**：`arriveAndDeregister` 只能扣调用会话配额、配额为零即拒——JDK 匿名 party 此处本是未定义行为，我们显式从严并声明；跨进程动态加入为**增强面**——JDK 句柄进程内、我们全集群同相合拢）；`PHASER_OP` 直发车道（判例 QUEUE/TOPIC/CONDITION），等待方按 `requestId` 过滤挂起闭环；`ClientMetrics.statusCodeOf` 扩 `PHASER_OP` 归线；握手常量升 10。
- **守卫回归两族（常驻条款）**：复制边界断言入 `replicated-state-machine`（每变异恰一条 `PHASER_OP_ENTRY`、等待/查询/取消零条目、跨副本 digest 逐字节一致、去重槽重放单计数、重启相位单调不回退、等待集随 term 清零无 ghost 重放、**编号证据基线 13→14 更替双代对照**）；快照扩维断言入 `snapshot-recovery`（`SnapshotLock` 自 35 起 phaser 字段全量往返、按字段恢复保真——phaser 是持久态原语，**不适用** topic/condition 零足迹条款，回滚口径同 barrier/队列型）。`RejectCodecTableTest` 扩 PHASER_OP 同型拒绝行（W10 判例常驻）。
- 测试：`PhaserEntryTest` 判定矩阵（配额增减归属/合拢单推进/去重重放单计数/配额摘除驱动提前合拢/已到场事实存续/归零空转复活/无条目到场拒绝/配置漂移不分歧/恢复往返）；`CoreEnginePhaserTest` 单机门面；`PhaserGatingTest`（v≤9 消息级拒绝不断连 + 七操作形状互斥矩阵（AWAIT_ADVANCE 必携 `expected_phase`、到场类必不携、`CANCEL` 必携 `await_request_id` 等）+ parties 钳制 + 撞 key 家族互拒 + QUERY 形状）；`ClusterPhaserTest` E2E（合拢矩阵 2×N/3×N、中途 REGISTER 加入当相位、`arriveAndDeregister` 提前合拢、**kill 进程死亡摘除不空转**——头号验收点，对标 Barrier 破障 E2E 形态、换主重挂无损耗 + 了结记录随 term、同 `request_id` 重发单到场、Follower 同型零副作用、并发不丢不重）；客户端 Scripted + `ClientPhaserIT`；协议冻结扩 v10 全量编号表 + presence 形态 codec 往返；`FairOrderingSuite` 豁免登记（判例 v5 D6：无 FIFO 授予序，合拢是广播事件、到场先后由 Raft apply 序承载并由确定性测试钉住）；config/vocabulary/控制台/快照夹具扩 phaser 维；换主类断言一律"有界总超时 + eventually 续醒"形态（v9 D12 纪律，W10/W11 教训）；集群测试并入共享 harness、控制 fork 端口数（既有套件纪律）。
- 基准与演练：`BenchmarkMain` 扩 phaser 相（到场受理 ops/s、K 方合拢推进延迟 P50/P99）入 `target/benchmark/`；滚动重启/LeaderKill 负载段扩 phaser 相；`-Pdrill` 全量复跑由用户在非沙箱单轮执行（红先保 `target/drill-logs/` 纪律）。
- 文档：ROADMAP **决策记录补三档立项裁决行**（2026-10-06，复刻 OCondition 行口径——需求信号未至提前立项、档位规则以本行登记为放行依据）+ 三档行状态 `未启动`→`进行中`（附本提案链接），归档时→`已落地`；双语指南 zh/en 对称扩章（01 §12 相位与配额 + 各原语速查行；03 OPhaser 章——三 Non-Goal 差异清单、死亡摘除与破障对照表、配额归属严格化惯用示例；05 `max-parties-per-phaser` 配置行 + **回滚窗口第四种口径注记**——phaser 有持久条目与快照字段，降级前确认无在途 phaser 流量（barrier/队列同型），与 topic/condition"天然干净"并列呈现、口径互不混读；07 控制台呈现；08 两新指标线 + 告警建议 + 五口径互引；09 排查"相位不推进"三分法——配额注册缺失/等待者未到场 vs W11 车道窗 vs 应用守卫谓词错，附 QUERY 只读判别路径；10 v1–v10 矩阵与门纪律行；术语表新增约 7 词）；WATCHLIST 登记 **W14**（热点 phaser key 条目率观察——每 party 每相位一条日志，暴露面与 W7 barrier 同量级、基线以本相报告为准）并在 **W11 行扩 v10 注记**（PHASER_OP 直发车道加入非 ACQUIRE 改道暴露面；等待侧因双通道重挂具自愈通道、与查询/到场侧的非对称性声明同 v8 topic 注记口径）。
- 纯增量发布，无 **BREAKING**：v1–v9 既有能力行为逐项不变；starter 不动（注解语义面向锁获取，判例 v6–v9 Non-Goal）；发布面沿用"仅客户端 SDK 链上 Central"裁决。

## Capabilities

### New Capabilities

（无——全部落在既有能力面上。）

### Modified Capabilities

- `wire-protocol`: v10 门与握手常量三处；`PHASER_OP` 消息对与七操作词表（阻塞位折叠、形状互斥矩阵、家族违例）；`LOCK_TYPE_PHASER=14`/`PHASER_OP_ENTRY=14` 编号落位与"止于 13"证据线更替条款（新证据线：`StatusCode` 止于 13 零新增、`LockType`/`RaftEntryType` 各止于 14）；parties 上限骑 `OVERLOADED` 的零新增条款；`QUERY` Leader 本地零日志读与线性化降级声明；管理面 phaser 字段续接。
- `core-lock-engine`: `PhaserEntry` 相位账簿状态机——每会话注册配额增减与归属、到场计数与去重槽幂等、合拢单推进（相位单调、arrived 清零、事件驱动全员唤醒）、了结记录有界窗口、死亡隐式摘除配额且已到场事实不撤销、摘除即合拢判定、归零空转可复活不终止、REGISTER 建条目其余操作无条目拒绝、条目存续不回收、`restored` 恢复往返。
- `lock-server`: v10 门控（v≤9 会话 `PHASER_OP` 消息级拒绝不断连）；变异操作 Leader 提交与等待/取消/查询 Leader 本地受理、Follower 同型 `NOT_LEADER` 零副作用；`max-parties-per-phaser` 配置与启动日志；合并深度护栏（等待项计 `max-queue-depth-per-key`）；结果→状态码映射延伸（`OVERLOADED` parties 线、`INVALID_REQUEST` 形状与无条目线）；三路等待回收接线（CANCEL/`closeSession` 摘除/换主清零）。
- `replicated-state-machine`: phaser 复制边界——每变异恰一条 `PHASER_OP_ENTRY`、等待/取消/查询零条目、apply 确定性与跨副本 digest 一致、去重槽重放单计数、相位与配额账簿跨换主/重启不回退、等待集与了结记录 Leader 易失随 term 清零、编号证据基线更替的常驻守卫条款。
- `snapshot-recovery`: `SnapshotLock` phaser 字段扩维（相位、注册总数、每会话配额表、当前到场计数、去重槽、了结记录）与逐字段恢复保真；快照家族往返夹具扩 phaser 维；持久态原语回滚口径条款（对照 topic/condition 零足迹分轨）。
- `client-sdk`: `OPhaser` 公开契约（降级/增强/保真三清单：无 onAdvance/终止/分层三砍差异声明、配额归属严格化、死亡隐式摘除、查询非实时一致、等待跨换主自愈、跨进程加入增强）、`newPhaser` 工厂与初始 parties 的会话记账、直发车道与等待挂起-通知-重发闭环、双通道自动重挂、超时 CANCEL 纪律、握手升 10。
- `admin-observability`: LIST_KEYS/KEY_DETAIL phaser 读数（相位/注册/到场计数 + 配额与等待明细，Leader-only 口径、Follower 如实零读）；`waiters` 合计口径计入 phaser 等待项；观察零扰动延伸。
- `admin-console`: 控制台 phaser 区段呈现（相位/注册/到场/等待明细；无内容外发面——纯计数与身份）。
- `metrics-observability`: `phaser.total{op,status}` 与 `phaser.parties.registered.max` 单一命名点、四口径命名避让注释互引扩五口径、`waiters` Gauge 计入 phaser 等待项口径。

- **openlatch-protocol**：`openlatch.proto` 纯增量（`MessageType.PHASER_OP=22`、`PhaserOp` 枚举、`PhaserOpRequest/Response`、`Envelope.payload` 槽 47/48、`LockType` 14、管理面 phaser 字段）；`raft.proto` 仅两处增量（`RaftEntryType.PHASER_OP_ENTRY=14`、`SnapshotLock` 自 35 起 phaser 字段）；契约冻结测试扩 v10 全量编号表；`ProtocolCodecTest` 扩 presence 形态往返。
