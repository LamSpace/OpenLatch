# Spec Delta: client-sdk

## MODIFIED Requirements

### Requirement: 断连快速失败与重连

连接断开时，所有挂起中的获取/释放/续租操作 MUST 以"服务不可用"异常快速失败。客户端 MUST 自动重连：指数退避（初始 200ms、倍增、上限 10s、每次 ±20% 抖动），直至成功或客户端关停；集群形态下重连目标 MUST 先试原地址，失败后按序轮询种子列表。重连成功 MUST 获得新会话，旧会话标识的残留响应 MUST 被丢弃。等待中的操作不因断连自动重试，由调用方决定重试。**出站取口 MUST 同代**：SDK 的每条业务出站请求 MUST 在"会话与通道同代"的取口下发出——取口时无活动会话（TCP 已连通但握手未完成、断连或重连窗）或取口期间发生会话换代时，该请求 MUST NOT 被写出到线路，MUST 以"服务不可用"异常**快速失败**（瞬态，可随重连后的下一次逻辑尝试重发）；SDK MUST NOT 把"TCP 已连通但尚未握手"的连接当作可发业务出站请求的连接。会话与通道 MUST 取自同一次取口：SDK MUST NOT 用某一代的会话编号去驱动另一代的通道写出的分支。**信封与其落点 MUST 同代**：当调用方持有会话快照（路由：登记时取定的会话 + 出站口）时，其出站 MUST 以该快照为**同代基准**——基准已非连接当前会话时 MUST NOT 写出（MUST 以"服务不可用"异常快速失败），SDK MUST NOT 让"按某一代会话编号的请求"落在另一代会话的连接上（服务端按连接判会话，跨代的去重槽不互相覆盖 ⇒ 不得静默重复生效）。持有快照的调用方 MUST NOT 绕过该基准直接取用裸出站口。**握手豁免限于握手路径**：`HELLO` 先于会话存在，故握手出站 MUST 走**显式的握手发送路径**（以本次连接刚建立的通道为出口，不查会话），该豁免 MUST NOT 被业务请求复用——业务出站 MUST NOT 借用握手通道绕过会话门。

#### Scenario: 断连时挂起操作快速失败

- **WHEN** 客户端持有挂起的获取请求时连接断开
- **THEN** 该请求以"服务不可用"异常快速失败，不阻塞到超时

#### Scenario: 自动重连恢复服务

- **WHEN** 服务端重启，客户端在退避窗口内重连成功
- **THEN** 后续请求在新会话上正常完成；旧会话的残留响应不影响新请求

#### Scenario: 原地址不可达轮询种子

- **WHEN** 客户端断连且原接入节点进程终止、种子列表中另有存活节点
- **THEN** 重连先试原地址失败后轮询至存活节点完成握手，全程受退避与请求超时约束、无无限等待

#### Scenario: 握手未完成期的业务请求不得写出

- **WHEN** 客户端 TCP 已连通（`HELLO` 已发出）但服务端尚未应答、会话尚未建立时，客户端发出业务请求
- **THEN** 该请求 MUST NOT 出现在服务端入站（零写出），本端以"服务不可用"异常快速失败；同一窗口内 `HELLO` 自身 MUST 已正常发出（握手不受会话门约束）

#### Scenario: 取口期间换代不得混代

- **WHEN** 业务请求取口期间连接换代（取会话与取通道之间会话已更新）
- **THEN** SDK MUST NOT 把该请求写出到新一代通道，MUST 以"服务不可用"异常快速失败；该请求不得以旧代编号落在新代通道上

#### Scenario: 握手豁免不适用于业务请求

- **WHEN** 客户端处于未建立会话的窗口（握手未完成），分别发出握手请求与业务请求
- **THEN** 握手请求经握手发送路径正常写出，业务请求以"服务不可用"异常快速失败且零写出——两者在同一窗口内的准入结果必须不同

#### Scenario: 陈旧路由的出站不得跨会话落点

- **WHEN** 调用方在会话 A 下取定路由（持有其会话快照），随后连接换代到会话 B（新会话已就绪），再经该**陈旧路由**发出业务请求
- **THEN** 该请求 MUST NOT 出现在服务端入站（零写出），本端 MUST 以"服务不可用"异常快速失败；SDK MUST NOT 以会话 A 的编号在新会话 B 的连接上落下一个新操作
