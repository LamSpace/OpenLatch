## MODIFIED Requirements

### Requirement: 快照内容完整性

快照 SHALL 承载复制状态全集：全部 key 条目——锁条目（key、模式、每个 (会话,线程) 持有者的计数、租约凭证、到期时刻、生效租期）、Semaphore 条目（总许可数、可用许可数、每个 (会话,线程) 持有者的持有数与其租约）、Latch 条目（key、初始计数、当前计数；条目存续即为已定型屏障）、ATOMIC 条目（key、形态、定型初值、当前值、版本戳、去重槽——最近已应用写操作的 (会话, op_seq) 与应答四元组；从未写过则为空槽；有值引用形态的初值/值/槽内 old_value/value 为字节串并按显式 presence 口径序列化——null 与空字节串可区分恢复，标量形态该四字节字段恒缺省）与 BARRIER 条目（key、parties、当前世代号、当前世代到场账簿——(会话, 请求) 集合、动作挂账 (会话, 请求, 世代) 或空、最近完结世代的了结记录——{世代, 结果 TRIPPED|BROKEN, 已了结的 (会话, 请求) 集合}；从未合拢或破障则了结记录为空）——与会话注册表（逻辑会话 id 集合，归属节点由其高位导出）。等待队列（锁等待者、Semaphore 等待者、Latch awaiter、Barrier 在队位次与通知时序）与服务端本地配置 MUST NOT 进入快照。快照序列化 MUST 使用已冻结的 `SnapshotState`/`SnapshotLock` 消息编号，MUST NOT 变更或复用既有字段号；v3/v4/v5/v6 扩展 MUST 仅以新增字段/新增条目形态表达。

#### Scenario: 快照内容清单

- **WHEN** 对含写持有、多读持有、重入计数、Semaphore 持有、Latch 计数、ATOMIC 值与去重槽（标量形态）、含 null/空串/恰限字节载荷与去重槽应答的有值引用 ATOMIC 形态、存续世代与动作挂账与最近了结记录的 BARRIER、存活会话与历史释放空洞的状态生成快照并解析
- **THEN** 各类型条目与会话集合逐字段完整，无等待队列与本地配置痕迹

#### Scenario: 序列化确定性

- **WHEN** 同一状态在两个副本上各生成一次快照
- **THEN** 序列化字节与全量摘要逐字节一致（条目序按声明的插入序保持）

#### Scenario: 含新条目的恢复往返

- **WHEN** 节点在 Semaphore、Latch、ATOMIC（含标量与有值引用两形态）与 BARRIER 状态存续时生成快照、以该快照重启并回放后续日志
- **THEN** 恢复后：许可扣减值与持有归属逐字段一致、租约到期驱动照常生效；Latch 计数与放行判定一致（归零条目恢复后 await 仍立即通过）；ATOMIC 值、版本戳与去重槽逐字段一致（有值引用形态的 null/空串/字节值与槽内载荷字节逐一保真、形态判别不混），重启后命中槽的重发请求仍不重复推进版本；BARRIER 世代号、到场账簿、动作挂账与了结记录逐字段一致——重启后旧世代等待项重发按了结记录裁决（TRIPPED/BROKEN），不重复计次，新到场进入恢复所得的当前世代续计

#### Scenario: 破障与回卷历史经恢复不腐

- **WHEN** 历经"合拢→回卷→破障→再合拢"多世代交叠的 barrier 条目经快照生成、重启与日志回放恢复
- **THEN** 条目终态 (generation, 账簿) 与恢复前逐字段一致，世代号单调不回退

#### Scenario: 旧版本快照向后兼容

- **WHEN** v6 服务端加载不含任何有值引用字段的既往快照（v4/v5 形态）并回放后续日志
- **THEN** 快照正常加载（新增字段按缺省解析），后续有值引用写入照常生效

## ADDED Requirements

### Requirement: 载荷快照尺寸有界

含载荷条目的快照 SHALL 尺寸可预期：每个有值引用条目的快照字节 MUST 由 `maxValueBytes` 与去重槽上限推导（每条目载荷存储 ≤ 2×`maxValueBytes` + 常数开销），全量快照文件尺寸 MUST 随（条目数 × 钳制上限）线性有界，MUST NOT 出现与写入次数成正比的累积膨胀（版本历史、槽外残留）。既有快照触发（`snapshot-threshold`，按条目数计）与保留（最近 2 份）纪律 MUST NOT 因载荷引入而改变触发口径；快照尺寸治理 MUST 以回归断言钉定（恰限载荷批量写入 → 生成快照 → 尺寸落界 → 安装与追赶回放正常），作为二档载荷原语共用基建的守门用例。`maxValueBytes` 下调 MUST NOT 使含更大既有载荷的快照失效或拒载（配置非快照判据）。

#### Scenario: 恰限载荷批量写后快照落界

- **WHEN** 对 N 个有值引用 key 各写入恰等于 `maxValueBytes` 的载荷并持续多轮版本推进，随后生成快照
- **THEN** 快照文件尺寸 ≤ N × (2×`maxValueBytes` + 常数) × 安全系数，且随版本推进次数无增长趋势；以该快照安装新副本后逐字段保真、追赶回放正常

#### Scenario: 钳制下调后旧快照照常加载

- **WHEN** 以 `maxValueBytes=4096` 写入载荷、配置下调为 1024 后重启加载原快照
- **THEN** 快照加载成功、存量值逐项可读；后续新写入按新限在接入层钳制
