# snapshot-recovery Specification

## Purpose

定义集群状态快照的生成、保留、加载与追赶行为：节点重启与新节点/落后节点加入时，凭"快照 + 增量日志"恢复到与集群一致的状态，且快照过程与恢复过程不破坏锁语义与服务可用性。
## Requirements

### Requirement: 快照内容完整性

快照 SHALL 承载复制状态全集：全部 key 条目——锁条目（key、模式、每个 (会话,线程) 持有者的计数、租约凭证、到期时刻、生效租期）、Semaphore 条目（总许可数、可用许可数、每个 (会话,线程) 持有者的持有数与其租约）、Latch 条目（key、初始计数、当前计数；条目存续即为已定型屏障）、ATOMIC 条目（key、形态、定型初值、当前值、版本戳、去重槽——最近已应用写操作的 (会话, op_seq) 与应答四元组；从未写过则为空槽；有值引用形态的初值/值/槽内 old_value/value 为字节串并按显式 presence 口径序列化——null 与空字节串可区分恢复，标量形态该四字节字段恒缺省）、BARRIER 条目（key、parties、当前世代号、当前世代到场账簿——(会话, 请求) 集合、动作挂账 (会话, 请求, 世代) 或空、最近完结世代的了结记录——{世代, 结果 TRIPPED|BROKEN, 已了结的 (会话, 请求) 集合}；从未合拢或破障则了结记录为空）、QUEUE 条目（key、形态判别、定型容量、元素列表——按队列序的 {载荷字节, 绝对到期时刻} 序列，**序列化序即队列序**、DELAY 形态到期时刻参与恢复且 QUEUE 形态恒 0/缺省、每会话去重槽表——{会话, op_seq, op, 已交付回执字节/列表}，从未写的会话无槽）、PHASER 条目（key、相位号、registered 总数、**每会话注册配额表**——{会话, parties} 按账簿插入序（注册先后=日志序）确定性导出、当前相位到场计数、到场去重槽——(会话, 请求) 集合（在场未推进周期内）、了结记录——最近一次推进的已通知未重发等待项集 {会话, 请求, 了结相位}，从未推进则为空）与 **TIMER 条目（key、代次号、装载态（armed）、绝对到期时刻——应用点折算值原样承载、MUST NOT 以相对延迟或判定标记入快照——与每会话装载去重槽表——{会话, request_id, op, 回声三元组} 按会话 id 升序导出，从未装载的会话无槽；代终结（DISARMED）亦保留账簿供观察，代内不存在"已到期"驻留位——到期为读面谓词，无复制足迹可载）**——与会话注册表（逻辑会话 id 集合，归属节点由其高位导出）。等待队列（锁等待者、Semaphore 等待者、Latch awaiter、Barrier 在队位次与通知时序、队列 put/take 双轨挂起与唤醒时序、**条件等待集——LockEntry 的 condition_name 等待队列、其登记时序与搬运/通知时序（v9，await 释放折叠的复制效果体现为持有清零本身，无需等待集入快照）**、**phaser 等待集与唤醒通知时序（v10，等待谓词由复制态相位账簿承载，等待项本身无复制来源——恢复后为空、客户端重挂补登记）**、**timer 等待集与唤醒通知时序（v11，同 v10 类目——等待谓词 = 装载态与到期时刻的纯函数，等待项本身无复制来源——恢复后为空、客户端重挂补登记）**）、topic 订阅登记表、每订阅缓冲、PUBLISH 去重槽与 topic_seq（topic 为 Leader 易失态，无复制状态可恢复——零日志边界的对偶条款）与服务端本地配置 MUST NOT 进入快照。快照序列化 MUST 使用已冻结的 `SnapshotState`/`SnapshotLock` 消息编号，MUST NOT 变更或复用既有字段号；v3/v4/v5/v6/v7 扩展 MUST 仅以新增字段/新增条目形态表达，v8 对该序列化面为零扩展（`SnapshotLock` 无 topic 字段即该条款的编号证据），**v9 同样零扩展（`SnapshotLock` 无 condition 字段——条件等待集不在快照面、await 效果由既有持有字段表达，即本条款的编号证据）**；v10 仅以新增 phaser 字段扩展（既有 1–34 号字段编号与语义零变更——v8/v9 的零扩展证据为各自版本的相对口径、后续 MUST NOT 复用为 phaser 变体字段），**v11 仅以新增 timer 字段扩展（既有 1–41 号字段编号与语义零变更——各代零扩展/续接证据为版本相对口径、后续 MUST NOT 复用为 timer 变体字段）**；phaser 等待集与通知时序 MUST NOT 进入快照（等待集恢复即清空的条款与 v9 条件集同构，差异在于 phaser 的**账簿**是复制态必须入快照——谓词在账簿、订阅在本地）**；timer 同构条款：账簿（代次/装载态/到期时刻/去重槽）入快照、等待集与通知时序不入（本条款即"到期零条目"裁决的快照侧对偶——不存在需要补偿的"fire 事件"足迹）**。

#### Scenario: 快照内容清单

- **WHEN** 对含写持有、多读持有、重入计数、Semaphore 持有、Latch 计数、ATOMIC 值与去重槽（标量形态）、含 null/空串/恰限字节载荷与去重槽应答的有值引用 ATOMIC 形态、存续世代与动作挂账与最近了结记录的 BARRIER、满容量含未到期元素的 DELAY_QUEUE 与带 TAKE 交付槽回执的 QUEUE 状态、**推进若干相位且含在场去重槽、了结记录与多会话配额的 PHASER（另有在集等待项与已通知未重发项）**、**含 PENDING 未到期装载、已到期共现钟与代终结（DISARMED）三形态且多会话去重槽在账、另有在集等待与已通知未重发项的 TIMER**、存活会话与历史释放空洞、同时承载多条件多等待者（含已搬运与在集两类形态）的状态生成快照并解析，其中存活会话同时承载 topic 订阅
- **THEN** 各类型条目与会话集合逐字段完整，无等待队列与本地配置痕迹；队列元素序与快照前逐一对应（含到期时刻与槽内交付字节）；订阅登记表、缓冲、去重槽与 topic_seq 在快照中零痕迹；**条件等待集与搬运/通知时序在快照中零痕迹——await 已生效的释放体现为该 key 无持有者，别无其他足迹**；**phaser 的相位/registered/配额表/arrived/去重槽/了结记录逐字段完整，而等待集与已通知未重发的时序状态零痕迹（换代窗口以其账簿形态入快照，通知行为本身不入）**；**TIMER 的代次/装载态/绝对到期时刻/去重槽逐字段完整（DISARMED 终态与"已到期但无驻留位"如实呈现——快照面无 marked 字段即派生裁决的编号证据），而等待集与已通知未重发的时序状态零痕迹**

#### Scenario: 序列化确定性

- **WHEN** 同一状态在两个副本上各生成一次快照
- **THEN** 序列化字节与全量摘要逐字节一致（条目序按声明的插入序保持；队列元素与去重槽表按声明的确定性序导出；**phaser 配额表按会话 id 升序、去重槽按 (会话, 请求) 确定性序、了结记录按登记到达序导出**；**timer 装载去重槽表按会话 id 升序导出（单槽覆盖式、每会话至多一行）**；条件等待集、phaser 等待集与 timer 等待集本不在序列化面，Follower 与 Leader 的快照互等）

#### Scenario: 含新条目的恢复往返

- **WHEN** 节点在 Semaphore、Latch、ATOMIC（含标量与有值引用两形态）、BARRIER、QUEUE/DELAY_QUEUE（含未到期元素与每会话交付槽）与 **PHASER（含非零相位、多会话配额、在场去重槽与了结记录）**、**TIMER（含未到期 PENDING、已到期无等待者共现钟与代终结三形态，及多会话去重槽回声）**状态存续时生成快照、以该快照重启并回放后续日志，日志中含折叠 await 条目
- **THEN** 恢复后：许可扣减值与持有归属逐字段一致、租约到期驱动照常生效；Latch 计数与放行判定一致（归零条目恢复后 await 仍立即通过）；ATOMIC 值、版本戳与去重槽逐字段一致（有值引用形态的 null/空串/字节值与槽内载荷字节逐一保真、形态判别不混），重启后命中槽的重发请求仍不重复推进版本；BARRIER 世代号、到场账簿、动作挂账与了结记录逐字段一致——重启后旧世代等待项重发按了结记录裁决（TRIPPED/BROKEN），不重复计次，新到场进入恢复所得的当前世代续计；队列深度、元素字节、绝对到期时刻与每会话槽逐一保真——重启后未到期元素仍不可见、到期后照常可消费、命中交付槽的重发仍返回同一份字节；**PHASER 相位号、registered、每会话配额、arrived、去重槽与了结记录逐一保真——重启后相位单调不回退、命中去重槽的旧到场重发不双计数、了结记录窗口内重发照常 `OK` 了结、窗口外迟到按新等待计**；**TIMER 代次、装载态、绝对到期时刻与去重槽逐一保真——重启后代次单调不回退、命中槽的重发装载回放声不双换代、已到期共现钟 AWAIT 重发即刻 `OK`、代终结钟即刻 `DENIED`、未到期钟续挂照常（恢复无需"补 fire"环节——到期无账簿位可回灌，此为派生裁决的恢复侧断言）**；**折叠 await 的释放半程经回放确定生效（恢复后该 key 无持有者），条件等待集恢复为空、不投递任何陈旧唤醒——客户端重挂（重发折叠 ACQUIRE，非持有者登记照常）后 SIGNAL 搬运与唤醒链路完全恢复**；topic 订阅与发布历史不参与恢复（重启节点登记表为空，客户端重挂后照常服务）；**phaser 与 timer 等待集恢复为空、不投递任何陈旧唤醒，客户端重挂命中恢复账簿——已推进/已到期即刻了结、未推进/未到期续挂，链路完全恢复**

#### Scenario: 破障与回卷历史经恢复不腐

- **WHEN** 历经"合拢→回卷→破障→再合拢"多世代交叠的 barrier 条目经快照生成、重启与日志回放恢复
- **THEN** 条目终态 (generation, 账簿) 与恢复前逐字段一致，世代号单调不回退

#### Scenario: 旧版本快照向后兼容

- **WHEN** v11 服务端加载不含 timer 字段的既往快照（v7/v8/v9/v10 形态）并回放后续日志
- **THEN** 快照正常加载（timer 字段按缺省解析），后续 SCHEDULE/DISARM 照常生效（v8/v9 对快照格式零变更、v10/v11 仅新增字段，多层兼容面与 v10 服务端逐项一致）
### Requirement: 快照触发与保留
系统 SHALL 在已应用日志条目数达到可配置阈值（`openlatch.cluster.snapshot-threshold`，默认 100 万）时自动触发快照，并 SHALL 提供手动触发通道供运维与测试驱动。每个节点 SHALL 保留最近 2 份快照，更早的自动清理。快照记录的位点 SHALL 等于其生成时刻的已应用位点。

#### Scenario: 阈值自动触发
- **WHEN** 持续提交条目使未快照位点数越过阈值
- **THEN** 该节点自动产出快照文件，位点等于当时的已应用位点

#### Scenario: 保留上限
- **WHEN** 连续成功触发三次快照
- **THEN** 数据目录内仅存最近 2 份

#### Scenario: 手动触发
- **WHEN** 通过手动触发通道请求快照
- **THEN** 立即产出一份新快照，效果与自动触发一致

### Requirement: 快照生成期间服务不中断
快照生成 MUST NOT 破坏一致性：快照内容 SHALL 取自某一应用时刻的完整状态（无撕裂）。生成期间状态机 SHALL 照常应用后续条目并响应客户端；被快照的锁状态 SHALL NOT 因生成过程而丢失后续变更（后续变更由增量日志承载）。

#### Scenario: 并发生成与负载
- **WHEN** 在持续获取/释放负载下触发快照
- **THEN** 负载请求无因快照而起的错误，快照状态 + 其后日志回放后与集群摘要收敛一致

### Requirement: 重启恢复 = 快照加载 + 日志回放
节点重启 SHALL 加载最新快照重建状态，其后仅回放快照位点之后的日志；已包含在快照中的条目 MUST NOT 被重复应用。恢复完成的节点其复制状态 SHALL 与集群其他副本全量一致（含后续当选 Leader 时正确驱动到期与写入的能力）。

#### Scenario: 快照点前后重启
- **WHEN** 节点停止期间集群产出快照并继续产生增量，节点重启
- **THEN** 节点装快照+回放尾部后摘要与集群一致

#### Scenario: 恢复后到期驱动生效
- **WHEN** 恢复完成的节点当选 Leader，其继承锁的租约到期
- **THEN** 到期条目被正常追加与复制，锁被释放

### Requirement: 落后与新增节点的快照安装追赶
落后超出日志保留窗口的节点、以及以空数据目录加入的新节点，SHALL 由集群侧安装 Leader 快照后继续增量追赶至一致；安装追赶期间该节点 MUST NOT 应用快照位点之前或重复位点之后的日志造成状态偏移。

#### Scenario: 严重落后节点追赶
- **WHEN** Follower 停止期间 Leader 快照截断了其仍需要的历史日志，Follower 重启
- **THEN** 该节点经快照安装（非本地全量回放）追平，摘要与集群一致

#### Scenario: 空目录新节点
- **WHEN** 以空数据目录启动的节点加入已持有锁状态的集群
- **THEN** 其安装快照并回放增量后与既有副本全量一致

### Requirement: 追赶期间对外行为
快照安装与增量追赶期间，节点 SHALL 可接受连接与 HELLO/PING/CLUSTER_VIEW 查询，写请求 SHALL 一律返回 `NOT_LEADER`（Leader 未知时按选举空窗呈现）。

#### Scenario: 追赶窗口写请求
- **WHEN** 节点处于快照安装/回放追赶中，客户端向其发 ACQUIRE/RELEASE/RENEW
- **THEN** 全部收到 NOT_LEADER，查询类请求正常应答

### Requirement: 恢复规模门槛与全量比对判据
10 万锁条目规模的快照恢复（加载 + 回放追赶）SHALL 在 30 秒内完成（§2.4 门槛）；快照大小、落盘耗时、加载耗时 SHALL 被基准测试度量并报告。恢复后与运行集群的一致性判定 MUST 采用全量比对（摘要级快速判定 + 结构级逐字段差异清单定位到 key/holder 粒度），MUST NOT 以抽样代替。

#### Scenario: 10 万条目基准
- **WHEN** 构造 10 万锁条目状态，生成快照并令一个节点走"装快照+回放"恢复
- **THEN** 恢复耗时 < 30s，全量比对通过，三项度量随报告输出

### Requirement: 载荷快照尺寸有界

含载荷条目的快照 SHALL 尺寸可预期：每个有值引用条目的快照字节 MUST 由 `maxValueBytes` 与去重槽上限推导（每条目载荷存储 ≤ 2×`maxValueBytes` + 常数开销），每个队列条目的快照字节 MUST 由 `capacity × maxValueBytes`（元素驻留）与每会话交付槽回执（`≤ 1 槽/会话 × maxElements×maxValueBytes` 的 DRAIN 交付上界，经 `max-drain-bytes` 预算钳制）推导，**每个 phaser 条目的快照字节 MUST 由 `max-parties-per-phaser`（配额表行数 ≤ 参与会话数、每会话 parties 为定长计数）与在场窗口推导（去重槽数 ≤ 当前相位已到场请求数、换代窗口项数 ≤ 最近一次推进的到场数——均随相位推进滚动清零/替换，MUST NOT 随历史相位/到场操作总量累积）**，**每个 timer 条目的快照字节 MUST 由常数三元组（代次/装载态/到期时刻）与装载去重槽推导（每会话恒为最近一槽、覆盖式替换——MUST NOT 随历史装载轮次累积，代历史与到期标记 MUST NOT 以任何形态驻留）**，全量快照文件尺寸 MUST 随（条目数 × 钳制上限）线性有界，MUST NOT 出现与写入/消费次数成正比的累积膨胀（历史元素副本、版本历史、槽外残留——每会话槽恒为最近一次；**phaser 的相位历史 MUST NOT 以任何形态驻留快照——账簿只呈当前 (phase, registered, arrived, 在场槽, 最近了结窗)**；**timer 的代次历史与到期驻留位 MUST NOT 存在——账簿只呈当前 (generation, armed, fire_at_ms, 每会话最近槽)**）。既有快照触发（`snapshot-threshold`，按条目数计）与保留（最近 2 份）纪律 MUST NOT 因载荷引入而改变触发口径；快照尺寸治理 MUST 以回归断言钉定（恰限载荷批量写入 → 生成快照 → 尺寸落界 → 安装与追赶回放正常），作为二档载荷原语共用基建的守门用例，且队列维度断言 MUST 覆盖"满容量 × 恰限元素 × 交付槽"三源叠加，topic 维度断言 MUST 覆盖"零增量"：纯 topic 负载下快照字节与同状态无 topic 基线逐字节相等（订阅登记表不在快照面），**条件维度断言 MUST 覆盖"零增量"：N 键 × M 条件等待者（含反复 await/signal/重挂交替）负载下快照字节与同持有状态无负载基线逐字节相等（等待集与搬运时序不在快照面，await 的复制足迹恰为一条既有条目与持有清零）**，**phaser 维度断言 MUST 覆盖"有界且滚动"：N 键 × 配额钳制上限 × 多轮相位推进的持续负载下快照字节 ≤ N × (常数 + b×配额上限 + c×在场窗) 且不随轮次增长；且同账簿终态、不同等待集构造的两份快照逐字节相等（等待集零快照足迹）**，**timer 维度断言 MUST 覆盖"有界且覆盖式"：N 键 × 多轮"装载→到期→再装载"持续负载（穿插等待与重挂）下快照字节 ≤ N × (常数 + d×会话槽) 且不随轮次增长；且同账簿终态、不同等待集/通知时序构造的两份快照逐字节相等（等待集零快照足迹）**。`maxValueBytes` 下调 MUST NOT 使含更大既有载荷的快照失效或拒载（配置非快照判据）。

#### Scenario: 恰限载荷批量写后快照落界

- **WHEN** 对 N 个有值引用 key 各写入恰等于 `maxValueBytes` 的载荷并持续多轮版本推进，随后生成快照
- **THEN** 快照文件尺寸 ≤ N × (2×`maxValueBytes` + 常数) × 安全系数，且随版本推进次数无增长趋势；以该快照安装新副本后逐字段保真、追赶回放正常

#### Scenario: 满容量队列快照落界

- **WHEN** 对 N 个队列 key 各写入至定型容量的恰限字节元素（含 DELAY 形态到期字段与每会话 TAKE 交付槽），多轮 put/take 交替推进后生成快照
- **THEN** 快照文件尺寸 ≤ N × (capacity×`maxValueBytes` + 槽交付预算 + 常数) × 安全系数，且不随 put/take 操作次数增长（深度恒定回填不构成累积）；以该快照安装新副本后元素序、到期时刻与槽回执逐字段保真、追赶回放正常

#### Scenario: topic 负载快照零增量

- **WHEN** 对 N 个 topic key 各建立 M 个订阅并持续多轮 PUBLISH/退订交替，随后生成快照；对照同规模无 topic 负载的基线快照
- **THEN** 两者快照字节与摘要逐字节相等（topic 负载贡献严格为零）；订阅数、缓冲深度与发布次数不以任何形式进入快照尺寸

#### Scenario: 条件等待负载快照零增量

- **WHEN** 对 N 个互斥锁 key 各建立 M 个条件等待者并持续多轮 await/signal/LEAVE/换主重挂交替，随后生成快照；对照同 N 键同持有状态无负载基线快照
- **THEN** 两者快照字节与摘要逐字节相等（等待集、搬运时序与 await 计数不以任何形式进入快照尺寸；await 的复制足迹已由日志条目承载，快照面无条件专属字段）

#### Scenario: 钳制下调后旧快照照常加载

- **WHEN** 以 `maxValueBytes=4096` 写入载荷、配置下调为 1024 后重启加载原快照
- **THEN** 快照加载成功、存量值逐项可读；后续新写入按新限在接入层钳制

#### Scenario: phaser 持续合拢快照尺寸有界

- **WHEN** 对 N 个 phaser key 各以配额上限附近的注册持续多轮"全员到场→合拢推进→再到场"交替（期间穿插等待、重挂与死亡摘除），随后生成快照
- **THEN** 快照文件尺寸 ≤ N × (常数 + 配额行上限 + 在场窗上限) × 安全系数且不随轮次增长（相位历史零驻留、去重槽随推进清空、了结记录单窗滚动）；以该快照安装新副本后相位号、配额与了结记录逐字段保真、重挂照常服务

#### Scenario: phaser 等待集零快照足迹

- **WHEN** 构造两个账簿终态 (phase, registered, arrived, 配额, 在场槽, 了结记录) 逐项相等、而等待集人数与已通知未重发时序不同的状态，分别生成快照
- **THEN** 两份快照字节与摘要逐字节相等（等待集与通知时序严格不入快照面）

#### Scenario: timer 持续装载快照尺寸有界

- **WHEN** 对 N 个 timer key 各持续多轮"装载→到期共见→再装载"交替（期间穿插等待、重挂与撤销），随后生成快照
- **THEN** 快照文件尺寸 ≤ N × (常数 + 会话槽行上限) × 安全系数且不随轮次增长（代次历史零驻留、每会话槽覆盖式恒最近一槽、无到期标记位——尺寸与装载次数解耦即派生裁决的尺寸证据）；以该快照安装新副本后代次、装载态与到期时刻逐字段保真、重挂照常服务

#### Scenario: timer 等待集零快照足迹

- **WHEN** 构造两个账簿终态 (generation, armed, fire_at_ms, 去重槽表) 逐项相等、而等待集人数与已通知未重发时序不同的状态，分别生成快照
- **THEN** 两份快照字节与摘要逐字节相等（等待集与通知时序严格不入快照面；"已到期"不使两份构造产生任何字节差——到期无位）
